# 2.5 视频生产配方与方法细节（Phase 42 定版沉淀）

> 本文件承载 SKILL.md「定版生产判据」的方法细节、反例与适用边界。
> 维护纪律：只写【方法 + 适用条件 + 禁用条件 + 失败修复方向】；具体项目的
> 镜头 ID、种子、逐图评语留在项目实验档案（证据索引：仓库根
> `PHASE42_VIDEO_SKILL_SEAL_ACCEPTANCE_REPORT.md` §5-§7）。模型字段与互斥

## 0. 证据边界（先读）

- 以下配方在 `agnes-video-2.5-flash` 上经真机探针+多轮用户逐图/逐链验收；
  换模型或换契约后全部重新验证，不得直接沿用。
- 「同配方足量候选中多数零瑕疵」是当轮经验观察，**不是模型保证**——跨种子
  方差真实存在（同配方某一种子可出现双人物/瑕疵，属正常数据点，不构成废配方）。
- 用户对人物、道具、场景、动作、整体观感拥有最终判断权；Agent 的筛选是
  预筛，不是验收。

## 1. 根帧层（身份敏感镜：CU/ECU/MCU 家族）

**默认动作**：auto 档已由系统定版（2026-09-30）——景别驱动的紧景别自动走
crop（approved Look 的头肩/面部确定性派生，`identity_crop_v1`）；派生失败
回落源参考媒体并记 `identity_crop_derivation_failed` 诊断（绝不静默）。

**反例 1（drop 的代价——画风漂移事故根因链）**：特写/中近景镜 Look 被静默
丢弃时，模型按 description 文本重造角色（画风、五官、标志特征全部自由发挥）；
i2v 把重造形象冻结进尾帧；裸尾帧接力沿链逐镜传播偏差风格。生成前核对真实
编译请求（sent/used/dropped refs），被 drop 必有 reason 可查。

**反例 2（keep 的代价）**：全身立绘 Look 进特写请求 → 构图被锚定在
「全身+环境」尺度（人物撑满画面/景别失控）。特写镜显式 keep 仅在用户明确
要求时使用。

**构图条款**：参考导致人物比例偏大时，在 prompt 加构图条款（人物小巧、
画面留白方向），配合 crop 使用。

**道具层**：入画道具必须绑 prop + 视觉状态注记（如「未点亮」「裂纹玻璃罩」
「泥水」）。反例：未绑 prop 的道具样式逐镜漂移（同一道具每镜外观不同）；
补绑定+状态注记后样式稳定。修复方向是补绑定，不是在 prompt 堆形容词。

**风格抢救（非常规手段）**：场景实例视图同发（keep_fullscene 形态）是把
画风/标志特征拉回正的最强锚，但会把构图锚死在「全身+环境」尺度、灵活性
下降——仅用于偏差抢救，不作为常规默认；使用后必须检查成片动作灵活性，
同一批/同链不得与其它配方混用（两个形象风险）。

## 2. 视频层（接力链）

**定版链式**：根帧先行（修正后的根帧作 i2v 硬首帧）→ 完成后提真实尾帧
（版本化文件名，自动托管）→ 下一镜双参考接力（尾帧=Picture 1 衔接动作/
空间，hero Look=Picture 2 再锚定身份/画风）→ 逐镜推进。

**双参考接线语义**：canonical 哨兵 `video_reference_asset_id="prev_tail_look"`
（agent 经 shot.update 显式设置；纯 relay `prev_tail` 行为逐字节不变）。
解析不到 hero Look = 结构化拒绝（fail closed），不静默降级为单参考。

**已知权衡**：Look 锚定与尾帧锚定竞争——端点帧里已冻结的偏差特征（如标志
斑纹的侧别）可能随尾帧胜出。结论：**双参考修复的是「沿链传播」，不修复
「端点本身」**——端点=根帧与尾帧两层：根帧有错先修根帧；**根帧正确但 i2v
过程中标志特征漂移时，尾帧即带偏差，同样先修（换种子重跑/换合格端点），
双参考不修复端点帧的偏差**（43.md 实证：根帧侧别✓→尾帧镜像→下游 5/5
候选镜像，换种子无效）。

**三参考接力（场景元素锚定）**：本镜剧情需要尾帧里看不到的场景元素（门/窗/
家具的位置与样式）时，用哨兵 `prev_tail_look_scene`——请求=尾帧+Look+本镜
SIV（Picture 3 指称=场景元素位置样式以此为准）。实证：修理间 SIV 的拱形门
先验不进请求时，三次生成出三种不存在的门；哨兵生效后门形态正确。**注意
约束与动作的平衡**：元素规格钉死过强会吃掉剧情动作（开门动作消失）——
修完元素必须复查动作仍在。

**反例（裸尾帧单参考接力）**：每镜只有上镜尾帧做参考时，画风/身份的偏差
自由度逐镜累积，无回正机制——偏差链的传播层成因。

**端点修复矩阵**（按问题类型选择，无万能修法）：

| 问题 | 修法 | 已知边界 |
|---|---|---|
| 空间错（没进该进的场景/构图） | 强化 description + 保留 relay | 画风/身份继承端点偏差 |
| 空间错（需跨空间转场） | 硬首帧转移（真实末帧作新镜首帧） | 下限由首帧质量决定 |
| 身份/画风漂移（空间正确） | 双参考接力逐镜回正 | 首段仍被端点帧拖拽，中后段回正 |
| 身份/画风要求最高、允许重构图 | 真解除 relay + 独立重生（完整锚定：场景 full + Look keep + 强化描述） | 空间自由度过大——必须先有场景先验；缺场景先停下走 Scene Agent 正式入口补场景（注意场景切换镜头跟随），再继续生产 |

**桥（keyframes 双帧）**：见关联技能 `keyframes-bridge-repair`——修复阶段
工具，双端合格且值得保留时才插；错误端点不插桥；普通首次生成不插桥。

**状态注记边界（模型能力，如实）**：i2v 根帧的视觉状态注记（如「未点亮」）
可能被模型忽略（43.md 实证：未点亮注记下灯仍发光，用户裁定=模型能力问题，
接受亮灯口径）。不要为状态注记反复烧配额；确需状态强一致时改用首帧视觉
（根帧画面对）而非文本注记硬约束。

## 3. 动作-时长-场景容量

- 时长超过场景/动作容量 → 模型凭空延伸场景（新地址凭空出现让人物继续跑）。
- 时长内动作不足 → 移速不自然、观感失真。
- 修复方向（可并用）：① 缩短时长；② 增加合理的后续动作填满时长（动作延伸
  =有效但不完全——场景延伸变短、人物表现更丰富，残留如实记录）。
- 快速动作镜（奔跑等）：少加多余动作——多余动作抢速度感、易不自然。

## 4. 候选策略与验收

- 同配方足量候选供逐镜挑选；候选间的取舍记录进 trace/评审材料。
- 五状态不混淆（见 SKILL.md）：实验候选 / 用户积极反馈 / 正式版本选定 /
  故事事实调整 / 下游批准，各走各的记录与批准——「已有好视频」不等于
  「已正式替换」。
- 验收维度：人物（身份标志逐项对照 approved Look）、道具（样式+状态）、
  场景（空间正确）、动作（自然+时长匹配）、整体观感。

## 5. 凭空场景元素的揭露路线（44A 终选沉淀）

**根因**：接力首帧（上镜尾帧）未包含目标场景元素时，镜头随人物移动、视野扩大，
模型只能在**已经照到的墙面**上现编元素（凭空出现）——文本约束与场景参考图都改
不了「第 0 帧未建立元素」这一帧层事实（判据 5 的修复不止哨兵+钉规格，还要选
「元素如何进入画面」的路线）。

**路线①：镜头跟随·盲区揭露（默认求稳）**
- 首帧保持接力连续性（上镜尾帧，场景零变动、零切换）；运动明确指向**首帧
  盲区**（画面没照到的方向），并显式写「镜头跟随平移」「元素随镜头移动在新
  显露的空间出现」——未知区域可以创建，揭露读作正常运镜。
- 哨兵三参考照发（元素规格以 SIV 为准）；接缝保持接力带（实测入缝≈接力带上段）。
- 适用：连续性优先、无全景建立需求（用户终选路线；「求稳」口径）。

**路线②：融合首帧·全景（按需选用）**
- 用户要求全景、或剧本需要建立镜（establishing shot）时：图像模型合成
  「起始状态全景」首帧——元素与人物起始状态一并成立，**元素置于人物身后的背景为
  基准构图**；再以该帧作硬首帧生成。
- 配方要点：opening_source=reference_previous（尾帧以 continuity_tail 追加为
  最后参考）+ first_frame_prompt_override 写起始状态构图 + **link_mode 必须
  为 i2v**（multi 模式构建不消费 boundary frames——硬首帧会被静默跳过）。
- 代价：入缝跳到切换带（全景 vs 上镜中近景的正常切换）；候选可能保留
  provider 环境音。

**音轨注记**：视频候选可能带 provider 环境音（不同候选差异真实存在）；
是否「有背景音」以用户听审为准（分贝测量不能替代听审）。后续需旁白/配乐
混音的项目，无声轨候选更易清洗——候选回执与评审材料应如实标注音轨差异。

**证据边界**：两路线的接缝区间来自单项目单元素的真实修复轮实测，是参照不是
模型保证；「未知区域可创建」的接受口径由用户裁定，Skill 记录的是决策入口
与机制，不预设审美结论。

## 6. 人数纪律（Phase51 B 定版，E2 对照实验实证）

**触发条件**：镜头画面应含 `shot.characters` 所列人物（宽/中景双人镜为主——
P50_B 用户看片观察「船上有时只有一人、有时没人」）。

**动作**（系统默认已接线，导演职责是文本层配合）：
1. 生成 prompt 的人数确定性由系统保证：`population_constraint` 参数默认
   true（导演工具 `shot.generate_images` / `shot.generate_videos`），按
   `shot.characters` 计数追加排除子句（"exactly N people…no other people"）。
2. 导演在 motion/description 文本中写明「谁在何处做什么」（角色+位置锚定）——
   E2 实证位置条款可控制站位（大副按条款站在船首 2/2），对跨镜衔接也有收益
   （B3：双人镜头明确谁在何处做什么）。

**禁用条件**：创作意图确需路人/人群/额外人物的镜头，工具参数显式
`population_constraint=false`（导演判断，不系统强加）。

**失败后处理**：候选人数不符（缺员/第三人）→ 视觉审查拦截，不进入保留
区间；重生成前先核对该镜生成请求的人数子句是否在（被 opt-out / legacy
路径无子句都是真实原因），再重试。

**证据位置**：`_p51_b_exp/`（E2：无条款 0/2 双人齐全[缺大副 2/2] vs 通用
条款 2/2 vs 角色+位置条款 2/2 且站位服从；E2V 视频层见 ledger）；接线修复
= Phase51 B population wiring（机制此前在生产路径休眠——image_adapter 有
子句函数但无人传入）。

## 7. 首帧方法反例：场景优先两步法（Phase51 B 实证，禁作默认解法）

**反例**：为修「首帧贴图感」（P50_B 用户观察）尝试的场景优先两步法——先
空场景图（作 image_ref）→ 再融入人物——在当前 provider 调用形状下有
**系统性空间复现缺陷**：base 图中的船被再次生成进画面（E1：2/2 候选出现
背景第二艘船，两 seed 一致=方法级缺陷非随机噪声）。

**结论**：
1. 不得将该方法作为贴图感的默认解法（会引入新的空间错误，比贴图感更严重）。
2. 「贴图感→i2v 人物僵死」不是方法级必现：E1 基线法（双 Look 参考直出）
   首帧在本实验镜头的融合度可接受，且 i2v 动作明确发生（非僵死）。贴图感
   与特定首帧（构图/姿态/景别）相关——防线=首帧审查增加融合度/合成感维度
   + 问题首帧定点重建，不是全局换生成方法。
3. P50_B 报告 §8.2-4 路径①（场景优先+人物融入）在当前调用形状下不可行，
   如实记录为能力边界；路径③（首帧审查维度）为当前可行方向。

**证据位置**：`_p51_b_exp/E1_*.png`（A 法 2/2 正确 vs B 法 2/2 船体复现）、
`E1V_A1/E1V_B1_frames/`（两法 i2v 动作均发生）。

## 8. 审核三查判据（协作流程 v2，2026-10-11 用户定版）

**判据**：审核（自动或人工）只负责三件事，面不能宽——
1. **人物**：模样/身份有没有出错（Look 身份变化、分身、发明人物）。
2. **环境**：跨镜有没有不一致（同一实体外观跳变、场景状态矛盾）。
3. **大不合理**：人数爆炸、叙事断裂、衔接失败。

**不拦**：资产「长成了什么样子」（只要它全流程是同一个实体）、偶发背景小瑕疵
（如远景帆船一闪——记录不拦）、与分镜文本的字面偏差。**分镜是拍摄蓝图，不是
逐帧验收标准**；固定资产一致性+衔接性完好=结果完好。

**Phase51-E 反例（判据错杀实证）**：s02_c04/s04_c04 按「水下暗影」分镜文本驳回
怪物揭示画面（三路约束"全败"），用户看片判断「怪物效果反而比较好」——审核
判据错杀合格品。审核判据修正后，怪物实体化类画面按一致性判定（同一实体+衔接
完好=通过）；海怪 Look 重做定版后，审核只查「是不是定版 Look」，不查「像不像
分镜想象」。

## 9. 尾帧接续链策略（tail-extension，协作流程 v2 增补，2026-10-11）

用户定版方向：Agnes 对尾帧接续的依从性最好（Phase51 实证 relay 衔接=用户验收
通过项）——**生成策略向接续链倾斜以增大容错率**；分镜规划保留。

**两种接续**（既有能力组合，不新建机制）：
1. **镜内接续（10s→20s）**：一段 10s 的尾帧→作为下一段的首帧输入继续生成
   10s→装配拼合 20s 长镜头。**容错核心：中途不合格只重做后半段**（跨 attempt
   累计使重做段不判死）；适用=动作连贯镜（追逐/操舵/持续位移），切换镜不适用。
2. **镜间接续**：尾帧→下一镜首帧参考（既有 relay/inherit_previous 路径），
   或尾帧直接生成下一视频（multi 参考模式）。

**接续链纪律**：
- 尾帧质量门：接续段的**尾帧**是下一段的输入——尾帧不合格（资产变样/构图崩）
  不得作为接续源，定点重生成该段尾帧。
- 起步/再锚定决策入口（§起步决策）照常适用：接续不豁免身份锚定检查。
- 修复 3 次未过→系统自动豁免跳过（executor repair_limit，协作流程 v2）：
  导演遇到豁免标记如实记录，不自行重试。
