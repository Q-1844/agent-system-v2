# 视频动作与因果策略（video-action-causality）

## 官方能力与生产政策（分开写清楚）

- **官方能力**：agnes-video-2.5-flash 时长 4–12 秒（`seconds` 字符串，默认
  "5"）；720P；mode=text/keyframe/reference 三者互斥。
- **本轮生产政策**：至少 8 秒、默认 10 秒、关键接触镜 10–12 秒（见 SKILL.md
  时长政策表）。8 秒下限是制作政策不是接口下限；默认 10 秒是本轮起始方案，
  尚无证据证明优于其他时长——C 批对照与 D 批实践就是检验它的证据。
- **失败判据与时长分开**：不合格的原因是拖沓、动作过载或缺少有效片段，
  不是"统一变长"或"统一变短"。加长不能挽救过载的动作；缩短不能制造剧情。

## 动作规划：起态 → 步骤 → 接触 → 结果 → 视角

每镜写提示词前先在规划字段里回答：

1. **起态**：谁、在哪、什么姿态、持有什么、与谁/什么接触。
2. **步骤**：动作的因果顺序——哪一步必须发生在哪一步之前。
3. **接触**：手/道具/人物之间的接触时刻——本轮最易出错、最必须可见的事件。
4. **结果**：动作完成后的状态（谁持有什么、位置关系如何变化）。
5. **视角**：机位、景别、是否随动；主动作与结果是否都在画面内。

较长的时长用于**准备、执行、结果和剪辑余量**，不用于塞入更多剧情任务。
主动作保持清晰、单一、有因果。

## 提示词删减规则：删冗余、保关键关系

- 删除：与画面无关的重复静态描述、在参考图里已经成立的信息、装饰性形容。
- **保留**：关键的持有者（谁拿着什么）、接触对象（和谁/什么接触）、动作
  方向、必须持续保持的关系（如"灯笼始终在男孩手中"）。
- 判断标准是**不冲突且足够明确**，不是字数最少。禁止把"不得重复静态信息"
  执行成删掉动作所需约束；也不反向堆成全员小传长文（长提示词质感基线对照
  见 first-frame-image.md，长文不默认更差，但每句都要有职责）。

## 模式选择（与槽位语义一致）

| 模式 | 何时用 | 请求形态 |
| --- | --- | --- |
| text | 无合适首帧、纯文生视频起镜 | 只 prompt + seconds |
| keyframe | 有合格首帧（硬边界）；双端钉住才用双帧 | first_frame（+last_frame 至少其一） |
| reference | 语义参考（Look/场景图/尾帧作参考，不锁首帧） | images 1–5 张 |

- keyframe 与 reference 字段**互斥**：一个请求只有一种模式的一组图参数。
  出站前自检：同一请求不得同时出现 first_frame/last_frame 与 images。
- Flash 不接受视频参考输入；标准版视频参考是收费能力备选，不在本轮免费
  主链内（不自动切换）。
- negative_prompt 无此字段：负面约束并入 prompt 文本表达。

## 生成后核对（工具成功 ≠ 视觉合格）

1. 回执与请求一致：model/mode/seconds；文件真实时长 ≥ 请求秒数 − 容差
   （实测 10 秒请求回 8.0s 属异常，记录并归档为失败样本）。
2. 完整播放（见 repair-diagnosis.md 审片顺序），核对：起态与首帧一致、
   步骤按因果发生、关键接触可见、结果状态成立、无中途人数/身份漂移。
3. 原生音轨默认保留（合格的环境声与动作声）；无旁白、无主动配音。
4. 每个结果标注：首次尝试或第几次返工；技术失败（网络/排队）与画面不合格
   重生分开统计。

## 拆镜判据

- 12 秒内主动作仍不清楚（跳步、分身、因果断裂）→ 拆镜。
- 拆出的每条新素材仍 ≥8 秒；两镜之间的衔接按 shot-continuity.md 决策。
- 不把"更长"当作单镜动作容量已扩大的证据；动作容量由起态/步骤/接触/结果
  是否都可见来检验。
