# 首帧生成策略（first-frame-image）

## 基线与谦逊声明

- 短提示词纯文生图质感好，来自 2026-10-06 图片优先批的用户观察（T1 短
  prompt 直出质感最好）。**这是待复验基线**：本轮在相同题目、模型、画幅下
  重新对照；不得声称它对所有题目或模型最优。
- 身份与质感都要达到作品要求；两者冲突时如实报告，不默认牺牲任何一方。

## 首帧只写可见关键信息

首帧提示词描述**画面里可见的东西**：人物、姿态、位置、道具与持有关系、
光线、构图。不写：剧情前史、心理活动、未入画的信息、把后续动作提前写进
静态帧。规划（剧情任务、动作步骤）与最终提示词分开——规划在分镜字段里，
提示词只承载画面。

## 按实际需求选择最小参考

| 情况 | 方法 |
| --- | --- |
| 单镜写实、无跨镜身份要求 | 可用无参考短提示词基线；说明其适用范围 |
| 同一人物跨镜、身份是硬要求 | 用必要身份依据（approved Look 参考图）；同时保留质感验收标准 |
| 需要具体空间状态 | 用场景状态图（SceneInstanceView）作空间依据 |
| 双人交接、多人构图 | 参考需覆盖人数与站位；生成后核对人数与分身 |

参考承担**身份约束**职责；若加入参考后质感掉到用户不可接受的范围，仍应
判失败——不以一致性改善抵消质感倒退。不要机械堆满所有参考：每一张参考
都要有明确职责（身份/空间/道具状态），无职责的参考不进请求。

## 首帧质量门（不过门不进视频）

生成首帧后先审图，以下任一命中即不合格：

1. **人数错误或分身**（多余的人、多余的肢体、同角色出现两次）——拦截，
   不以"视频阶段可能自愈"放行（自愈不可依赖，见正式链 Phase48 结论）。
2. **道具持有者错误**（道具在错误的人手里/悬空）——阻止以该错误状态生成
   依赖视频；修首帧根因。
3. **起始状态冲突**（首帧已是动作完成态，而本镜要求从准备开始）——识别
   规划与首帧的冲突，修正确起态；不硬启。
4. **身份特征错误**（对照 approved Look：发型识别特征、关键道具主色、
   人物身份标志）——即使局部，若是识别性特征也判不合格。
5. **构图与景别不符**（计划中近景，出了远景构图）——重建，不在视频里硬拉。

伪影检查：肢体错误、透视崩坏、多余元素——不合格图不进任何视频请求
（含 keyframes 的结束帧：结束帧是图像产物，先审图再进请求）。

## 与视频的关系

- i2v/keyframes 的首帧是**硬边界**；multi 的参考图是语义参考（不锁首帧）。
  选哪种模式由本镜衔接要求决定（见 shot-continuity.md），不因首帧好/坏而
  混淆槽位语义。
- 首帧不合格时：记录为首帧失败，修好再生成视频；**不偷偷换图再报告视频
  首次尝试成功**。
