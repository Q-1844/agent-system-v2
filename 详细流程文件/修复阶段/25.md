# Sequence S2 — Audio Layer Foundation

## 0. 当前基线

上游已经正式完成：

```text
SHOT PRODUCTION BACKEND V1
FREEZE

SEQUENCE S1 ASSEMBLY FOUNDATION
FINAL PASS
```

S1 已证明：

```text
多个 authoritative Shot
→ SequenceBlock
→ hard-cut AV assembly
→ SequenceRenderVersion

ordering ✓
trim ✓
native audio preservation ✓
duration ✓
AV sync ✓
basis ✓
freshness ✓
race guard ✓
explicit version selection ✓
```

本阶段不得重新设计 S1。

---

# 1. 本阶段解决的问题

S1 解决的是：

> 几个有声 Shot 怎么可靠连接。

S2 解决的是：

> **连接完成以后，如何在整段 Sequence 时间轴上增加跨 Shot 的声音层。**

包括第一版：

```text
Background Music
Narration
Sequence-level Ambience
Basic Gain
Fade In / Fade Out
```

最终得到：

```text
Shot native AV
        +
Sequence audio layers
        ↓
SequenceRenderVersion
```

---

# 2. 一个重要架构原则

本阶段严格区分：

```text
Audio Source Generation
```

与：

```text
Audio Timeline / Mixing
```

S2 负责第二个。

不要把：

```text
音乐模型
旁白模型
环境音模型
```

直接写死进 Sequence renderer。

正确结构：

```text
Audio Source
        ↓
Audio Artifact
        ↓
Sequence Audio Layer
        ↓
Sequence Mixer
```

Audio Artifact 可以未来来自：

```text
A1 narration
project audio resource
user imported audio
future music generator
future ambience generator
```

但 Sequence Mixer 不应该关心：

> 这个 WAV/MP3 是谁生成的。

---

# 3. 本阶段不要建立 AI Music Provider

明确暂不实现：

```text
Music Agent
Music Generation Provider
Music Prompt System
Music Style Agent
automatic soundtrack composer
```

原因：

> Sequence timeline/mixing 还没有成立之前，直接研究音乐生成属于倒序开发。

首先让系统能够可靠表达：

```text
这段音乐
从什么时候开始
到什么时候结束
音量多少
怎么淡入
怎么淡出
```

以后换任何音乐来源都可以直接使用。

---

# 4. A1 的正式位置

此前已经完成的 A1 Voice Foundation 继续保留。

它现在的主要正式用途之一是：

```text
Narration
```

如果现有 A1 API / artifact 可以直接提供 narration WAV：

复用。

不要复制 VoiceGenerationPack。

不要重新建设：

```text

```

如果 A1 当前接口只围绕 DialogueAudioVersion：

先审计是否可以在不破坏 frozen behavior 的情况下作为 narration source 使用。

只做必要 adapter。

不要重构 A1。

# 7. 建立独立 SequenceAudioPlan

在现有：

```text
src/sequence/
```

domain 内增加：

```text
SequenceAudioPlan
```

它不是新的产品模块。

它是 Sequence Assembly 的声音侧 canonical。

推荐最小结构：

```text
SequenceAudioPlan:
    sequence_id
    revision

    layers:
        - layer_id
          role
          source
          start_ms
          source_in_ms
          duration_ms
          gain_db
          fade_in_ms
          fade_out_ms
```

---

# 8. role 第一版严格限制

只允许：

```text
music
narration
ambience
```

不要现在增加：

```text
dialogue
foley
sfx
voice_replacement
lip_sync
stem
bus
master
```

Shot 内：

```text
dialogue
lip-sync
local SFX
local ambience
```

已经属于 native AV。

不得在 Sequence 层重新拥有它们。

---

# 9. Source Reference

`source` 不得只是随意持久化的绝对文件路径。

先审计项目现有 artifact/resource contract。

优先表达类似：

```text
source:
    artifact_type
    artifact_id
```

或仓库已有稳定引用结构。

执行时：

```text
artifact reference
→ resolve actual file
```

如果当前资源系统确实没有通用音频 source reference：

允许建立一个非常薄的：

```text
SequenceAudioSourceRef
```

但它只能引用已有 artifact。

不要复制音频文件本身。

---

# 10. Audio source truth

S2 不允许：

```text
扫描目录找最新音频
mtime 猜 source
glob *.wav
默认取数组最后一个
```

必须由明确 source reference 解析。

解析不到：

```text
FAIL CLOSED
```

---

# 11. 时间轴全部使用 Sequence 时间

S2 的时间坐标：

```text
0ms
```

表示：

> Sequence Render 的第一帧。

不是某个 Shot 的局部时间。

例如：

```text
Sequence = 22.8s

music:
start = 0
duration = 22800

narration:
start = 4200
duration = 5300

ambience:
start = 8000
duration = 14000
```

---

# 12. start_ms

定义：

```text
start_ms
```

= Audio Layer 在 Sequence timeline 上开始的位置。

要求：

```text
start_ms >= 0
```

超出 Sequence duration：

```text
FAIL CLOSED
```

不要静默裁成片尾。

---

# 13. source_in_ms

允许从原音频内部跳过一部分。

例如：

```text
music source = 60s
source_in_ms = 12000
```

表示从第 12 秒开始使用。

要求：

```text
0 <= source_in_ms < source_duration
```

---

# 14. duration_ms

第一版采用显式：

```text
duration_ms
```

表示当前 layer 在 Sequence 中使用多长。

必须满足：

```text
source_in_ms + duration_ms
<=
source_duration
```

以及：

```text
start_ms + duration_ms
<=
sequence_duration
```

非法：

```text
FAIL CLOSED
```

不要偷偷 loop。

---

# 15. Music 暂不支持自动 Loop

S2 第一版不要实现：

```text
auto loop
beat-aware loop
AI extend
time stretch
```

如果音乐长度不足：

要求调用者提供足够长的 source 或明确裁切。

以后真实使用证明 loop 很常见时再做。

---

# 16. Gain

每层支持：

```text
gain_db
```

例如：

```text
music      -18 dB
narration   -3 dB
ambience   -12 dB
```

但不要把这些数值做成系统魔法默认值。

可以有保守 UI/API default：

```text
0 dB
```

调用者明确配置。

未来 Agent/Skills 学习：

> 什么情况下音乐应该是多少 dB。

系统只提供控制能力。

---

# 17. Fade

支持：

```text
fade_in_ms
fade_out_ms
```

要求：

```text
>= 0

fade_in_ms + fade_out_ms
<= duration_ms
```

第一版只做线性或 ffmpeg 现有稳定 fade 类型。

不要建立：

```text
fade curve editor
Bezier automation
keyframe volume envelope
```

---

# 18. Native Shot Audio 永远是 Base Layer

S1 Render 中已经存在：

```text
Shot native audio
```

S2 必须：

```text
保留它
```

然后叠加：

```text
music
narration
ambience
```

不要：

```text
extract dialogue
replace native audio
source separate
redo lip-sync
```

结构：

```text
S1 native AV base
        +
audio layer 1
        +
audio layer 2
        +
audio layer N
        ↓
mixed SequenceRenderVersion
```

---

# 19. 不实现自动 Ducking

第一版先不要做：

```text
检测对白
自动降低 BGM
sidechain compressor
speech-aware ducking
```

这些属于后续质量层。

目前用户/Agent 可以：

```text
设置 music gain
设计 layer start/end
设置 fades
```

先验证基本控制面是否已经足够灵活。

---

# 20. 不实现 Loudness Normalization

S2 也暂时不要做：

```text
LUFS target
automatic gain normalization
compressor
master limiter
full-film loudness matching
```

这些属于我们之前定义的第三层：

> **Collective Calibration。**

S2 只做：

```text
layer-level gain
+
fade
+
mix
```

---

# 21. 但必须做 clipping advisory

混音以后机器可以检测：

```text
peak level
```

如果存在明显 clipping 风险：

返回：

```text
audio_peak_warning
```

但第一版：

```text
不自动改 gain
```

系统负责发现问题。

用户/Agent 决定如何调整。

---

# 22. 不重复渲染 Shot

S2 不调用：

```text
Agnes
Shot Video Generation
Native AV generation
```

来源是现有 Sequence 当前所使用的 authoritative Shot media。

任何 audio plan 修改：

```text
只重新 render Sequence
```

不能触发 Shot regeneration。

---

# 23. S1 Render 是否作为 Base

首先审计两种实现。

## 方案 A

```text
SequenceBlock
→ S1 base render
→ audio mix
```

## 方案 B

```text
SequenceBlock
+ AudioPlan
→ 一次完整 Sequence render
```

选择原则：

> 最少重复转码、最清晰 provenance、最少 truth duplication。

不要机械执行规格示例。

如果使用方案 A：

必须要求 base SequenceRenderVersion：

```text
CURRENT
```

如果 base stale：

```text
FAIL CLOSED
```

如果方案 B 更符合当前 media_ops 架构：

可以直接复用 TimelinePlan 从 authoritative Shot 重建。

报告必须解释选择。

# 28. Audio Source 变化

如果 audio source artifact ID 不变但底层文件内容改变：

```text

```

```text

```

---

# 29. Sequence canonical 与 Audio canonical 独立 revision

例如：

```text
Sequence clips 未变
Audio gain 改了
```

应该：

```text
SequenceBlock revision 不变
SequenceAudioPlan revision 改变
```

反过来：

```text
Shot order 改了
```

AudioPlan 本身不一定改。

但当前 final render：

```text
STALE
```

因为 base Sequence timeline 改了。

这就是两个不同 truth domain。

# 30. Race Guard

继续使用 S1 三阶段模式。

Phase 1：

```text
resolve timeline
resolve source videos
resolve audio plan
resolve audio artifacts
snapshot basis
```

Phase 2：

```text
ffmpeg render/mix
```

不持 project lock。

Phase 3：

```text
recompute basis
```

如果期间：

```text
Sequence clips changed
Shot final_video changed
Audio Plan changed
Audio source changed
```

则：

```text
sequence_dependency_changed_before_commit
```

输出可以留 evidence。

不得 attach 为 CURRENT。

# 53. 最终原则

Shot 层负责：

```text
角色表演
对白
lip-sync
动作同步 SFX
local ambience
```

Sequence 层负责：

```text
几个 Shot 的连续时间
背景音乐
旁白
跨镜 ambience
audio overlays
```

未来 calibration 层负责：

```text
整个片段听起来是否平衡一致
```

不要重新混淆 ownership。

S2 只建设：

> **“几个优秀有声镜头连接以后，系统有没有能力在它们上方可靠地组织连续声音。”**

如果答案成立：

停止扩系统。

留给未来 Agent + Skills。
