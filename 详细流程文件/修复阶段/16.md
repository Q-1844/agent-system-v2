# Audio V1 — Phase A2

## Dialogue Timing + Lip-sync Production + Duration / Speaker Adaptation

当前 Audio V1 Phase A1 已正式完成。

A1 已证明：

```text
Shot.dialogue
    ↓
CharacterVoiceProfile
    ↓
VoiceGenerationPack
    ↓
MiniMax Speech 2.8 Turbo
    ↓
DialogueAudioVersion
    ↓
production WAV 48kHz / mono
```

并且已经成立：

```text
Voice Foundation architecture PASS
MiniMax provider TECHNICALLY SUITABLE
人工听评 PASS
Voice quality CONFIRMED
全量 regression PASS
```

用户已经明确决定：

> TTS 声音质量不再继续测试。
>
> 当前重点转向：
>
> 1. 音画同步
> 2. 音视频时长适配
> 3. 不同镜头 / 多人物 / 角度条件下的 lip-sync 适配
>
> 可以先推进较完整的生产实现，再做少量真实测试。

因此本阶段不是：

```text
Voice bake-off
TTS quality experiment
MiniMax vs ElevenLabs
Voice Design / Clone experiment
```

本阶段正式定义为：

> **建立从“已选择的 DialogueAudio + 已选择的 Visual Video”到“可版本化、可 stale、可审核的 Lip-synced Video Artifact”的完整生产后端。**

# 6. 时长适配是本阶段核心问题

这里必须把策略做正确。

## Case A — Video 比 DialogueAudio 长

例如：

```text
video = 5.0s
dialogue = 3.7s
```

这是正常生产情况。

不要：

```text
截短 video 到 3.7s
```

默认应该保留完整视觉镜头。

建立一个用于 Lip-sync 的：

```text
sync_input.wav
```

内容概念：

```text
[lead silence]
[approved dialogue audio]
[tail silence]
```

最终：

```text
sync_input.wav duration
≈ source video duration
```

允许：

```text
speech_start_ms
```

作为显式 generation 参数。

第一版默认可以：

```text
speech_start_ms = 0
```

但接口必须留下。

注意：

> `sync_input.wav` 是 derived working artifact。

它不是新的 DialogueAudioVersion。

不得写回：

```text
dialogue_audio.json
```

不得改变 approved Voice artifact。

如果需要展示 adjusted word timestamps：

根据 `speech_start_ms` 派生即可。

不要修改 A1 原始 timestamp。

# 7. Audio 比 Video 长

例如：

```text
video = 4.0s
```

让未来上层明确知道：

> 这个镜头视觉长度不足以承载当前正式对白。

这是非常重要的 production signal。

# 10. Speaker Target

A1 已经解决：

```text
谁在说话
```

但 Lip-sync 还要解决：

```text
画面里的哪一张脸要动
```

这是两个不同的问题。

不要混为一谈。

设计：

```text
LipSyncSpeakerTarget
```

可以是 generation input / derived options。

至少支持概念：

```text
single_visible_speaker
auto_detect
manual_target
```

manual target 可以表达：

```text
frame_number
coordinates
```

如果 provider 支持 bounding boxes，也可作为 provider-specific extension。

# 11. 多角色 Shot 不能猜

如果：

```text
Shot.characters = [Alice, Bob]
Dialogue speaker = Alice
```

这并不意味着程序知道视频中哪一张脸是 Alice。

因此：

默认不得把：

```text
character_name
```

直接伪装成：

```text
face coordinates
```

如果当前没有视觉 Character → face track mapping：

### V1 规则

单人物镜头：

```text
允许自动 speaker targeting
```

多人物镜头：

如果没有：

```text
manual target
或明确 provider auto-detect 策略
```

则：

```text
MULTI_FACE_TARGET_REQUIRED
```

fail closed。

不要静默同步“画面里最大的脸”。

如果 caller 显式选择：

```text
auto_detect
```

允许调用 provider。

但：

```text
selection_mode = auto_detect
```

必须进入 generation_basis。

# 28. 自动测试策略

这次不要把阶段主要精力放在“声音质量测试”。

但生产契约必须有 deterministic tests。

测试重点：

### Truth / readiness

```text
missing audio
stale audio
missing video
stale video
ready
```

### Timing

```text
video 5s / audio 3s
→ padded sync input = 5s

lead-in offset
→ timestamps correctly shifted

audio > video
→ VIDEO_TOO_SHORT

no dialogue truncation
```

### Speaker

```text
single speaker
multi-character + no target → blocked
manual target
auto_detect explicit
```

### Pack

```text
determinism
actual-dependencies-only
complete basis
```

### Generation

```text
provider success
provider failure
timeout
bad output
download failure
```

### Race

至少：

```text
audio changes during lip-sync
video changes during lip-sync
speaker/timing changes during lip-sync
```

都必须 reject attach。

### Artifact

```text
raw provider output kept
production review mux created
ffprobe real
explicit selected pointer
approval independent
```

### Freshness

```text
audio change → stale
video change → stale
timing change → stale
unrelated shot change → remains current
unrelated character change → remains current
```

### Safety

```text
SYNC_API_KEY never serialized/logged
```

不需要为了测试数量追求 100+ cases。

覆盖契约即可。
