3\. 当前最影响成片质量的三个瓶颈



我目前会把前三名排成下面三个，而不是笼统说“模型不够强”。



瓶颈 A：进入视频之前的视觉起点是否正确



类型：分镜图片 / 资产 / Binding。



包括：



Character Look 是否真正 on-model；



姿态是否适合当前 Shot；



Location/SIV 是否正确；



构图是否正确；



首帧人物是否太远导致身份信息不足；



Look / Prop / scene refs 是否被正确绑定；



tail 是否本身已经漂移。



视频模型从错误首帧开始，很难靠 motion prompt 救回来。



当前 s02\_c02 的实验恰好说明了这一点：重新注入角色身份信息可能比继续机械 relay 更重要。



瓶颈 B：视频模型内部的时间漂移



类型：Provider / video model。



即使 first frame 正确，仍然可能出现：



人脸／角色形态随时间漂；



羽毛、手、脚、翅膀、道具变形；



远景 → 近景重新“发明”角色；



小道具消失；



动作终点不准确；



连续 relay 逐镜积累误差。



这不是 Skill 能完全修掉的。



系统可以：



重锚；



换模型；



换 mode；



生成更多候选；



用 first/last frame；



用 reference；



重做错误镜头。



但模型最后还是决定像素。



研究报告本身也明确区分了“系统确保输入正确”和“模型确保最终视觉保真度”。



瓶颈 C：Agent 是否能正确选择方法，并正确理解当前生产事实



类型：Agent / Skill / 项目依赖。



这是最近最核心的新瓶颈。



系统底层已经能做很多事，但 Agent 仍可能：



不知道该用哪个 Skill；



把组首和组内混淆；



机械继续 relay；



忘记重新注入 Look；



正常切镜却硬桥接；



没核对 receipt 就宣称完成；



误用旧尾帧；



不检查 downstream stale；



读到旧 asset/version。



这也是为什么你后来先建设 Skill，而不是继续往 Agent system prompt 里堆规则。
