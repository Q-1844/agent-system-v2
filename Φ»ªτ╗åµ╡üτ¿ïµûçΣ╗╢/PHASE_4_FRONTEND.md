# 阶段 4 · 前端重构（布局与交互，不含样式）

> **目标**：把「六个平行页面 + 聊天式操作」重构为「三栏编辑器 + 时间线 + 队列面板」。
> **约束**：本文档**只规定布局结构、组件划分、数据流、交互行为**。视觉样式（配色、间距、圆角、动效）由实现者自行决定，不做规定。
> **前置**：阶段 1、2、3 全部验收通过。
> **参考开源项目**：`reference/agnes-video-generator/static/index.html`（单文件 SPA，可参考它的任务进度面板和参数表单组织方式；但它是纯 HTML+Tailwind，我们是 Vue3+Naive UI，只借鉴信息架构，不抄代码）

---

## 4.1 为什么要大改

现在是六个平行页面：仪表盘 / 剧本 / 角色 / 分镜 / 动画 / 音频 / 设置。用户要做一个片子，得在六个页面之间反复横跳，而且每个页面只能看到自己那一块的状态。

**这类工具的正确形态不是"多个页面"，而是"一个编辑器"。** 参照的是剪辑软件而非 CMS。

而且在视频 1 RPM 的现实下——**任务队列的可视化就是这个产品的灵魂**。用户最关心的问题是「我的任务排到第几了、还要多久、哪个失败了」。其它都是化妆。

## 4.5 ShotCard 规格（最重要的组件）

一张卡片必须能一眼看完这个镜头的全部状态。

```
┌─────────────────────────┐
│ ●  s01_c02      🔒 ⋮    │  ← 状态灯 + 镜头号 + 锁定 + 更多菜单
│ ┌─────────────────────┐ │
│ │                     │ │  ← 首帧缩略图（无图时显示占位 + "生成分镜图"按钮）
│ │   [首帧缩略图]      │ │     视频已生成时：hover 播放 mp4
│ │                  ⏵  │ │     keyframes 模式：右下角小角标显示尾帧缩略图
│ └─────────────────────┘ │
│ 中景 · 推轨 · 5.2s      │  ← 景别 / 运镜 / 时长（用 seconds_returned）
│ 「你逃不掉的。」         │  ← 台词，超长截断
│ [i2v] [🖼][🔊][🎬]      │  ← link_mode 徽标 + 三个产物状态图标
└─────────────────────────┘
```

### 状态灯规则

| 灯 | 含义 | 判定 |
|---|---|---|
| ○ 空心 | 未开始 | 三个产物都 pending |
| ◐ 半环转动 | 生成中 | 有任一产物 generating，或有 job running |
| ◔ 虚线环 | 排队中 | 有 job queued（**并显示队列位次**） |
| ● 实心 | 完成 | video.ready |
| ◑ 部分 | 部分完成 | first_frame 好了但 video 没好 |
| ✕ | 失败 | 有任一产物 failed |
| 🔒 | 锁定 | `locked == true` |

### 三个产物图标

`🖼 分镜图` / `🔊 配音` / `🎬 视频`，每个图标三态：灰（未做）、黄（进行中）、亮（完成）、红（失败）。**点图标直接触发对应生成。**

### 卡片交互

- 单击 → 选中，右侧 Inspector 切换
- 双击 → 打开大图预览 / 播放视频
- Shift+点击 → 范围多选；Ctrl/Cmd+点击 → 追加多选
- 拖拽 → 调整镜头顺序（同场次内），跨场次拖拽 = 移动镜头
- 右键菜单 → 复制镜头 / 在此后插入 / 删除 / 锁定 / 重新生成 / 拆分台词

### 多选后的批量操作条

选中 2 个以上时，网格顶部浮出操作条：
`已选 5 个镜头  [生成分镜图] [生成配音] [生成视频] [锁定] [删除]`

```
┌────────────────────────────────────┐

│ ▶ 运行中                            │

│   轮询中 63%（已等 118s）           │
│   ████████████░░░░░░  [取消]        │
├────────────────────────────────────┤
│ ⏳ 排队中 (3)          预计 3分30秒 │
│   1. s02_c02 · 视频      ~70s      │
│   2. s02_c03 · 视频     ~140s      │
│   3. s03_c01 · 视频     ~210s      │
│   ⓘ 视频模型限速 1 次/分钟，        │
│      任务将自动串行执行             │
├────────────────────────────────────┤
│ ✕ 失败 (1)         [全部重试]       │
│   s01_c04 · 视频                    │
│   首帧缺少公网 URL                  │
│   [重试] [查看详情] [定位到镜头]     │
└────────────────────────────────────┘
```

### 🔴 三个不可省略的设计

1. **明确告知 1 RPM 限制**，并解释"这不是卡住了，是在排队"。不解释的话用户会以为程序挂了，然后疯狂点重试，把队列塞爆。
2. **失败任务的错误信息必须是人话**，不能是 `Exception: 400 Bad Request`。后端 preflight 已经给了可读文案，前端直接展示。
3. **"定位到镜头"按钮** —— 点了自动滚动到 ShotGrid 中对应的卡片并选中。

## 4.7 Timeline 规格

三条轨道，横向可缩放（Ctrl+滚轮），点击定位。

| 轨道 | 内容 | 数据来源 |
|---|---|---|
| 视频轨 | 每个 Shot 一个色块，宽度 ∝ 时长 | `video.seconds_returned` 优先，回退到 `num_frames/frame_rate` |
| 音频轨 | 波形示意（可以只画矩形，不必真解码） | `audio.duration_ms` |
| 字幕轨 | 字幕文本块 | `audio.words` 经 `words_to_cues` |

**🔴 音频轨比视频轨长的镜头要用醒目颜色标出** —— 那是音画不同步的直接可视化，也是阶段 2 修正的验证工具。

时间线也是「拼接顺序」的唯一真相：拖拽视频轨的色块可以调整镜头顺序。

## 4.8 状态管理（Pinia）

```
src/store/
├── project.ts    当前项目（Project 对象）、选中的 shot_ids、CRUD
├── jobs.ts       任务队列状态（由全局 SSE 驱动）
└── system.ts     限流快照、配额、设置
```

### 🔴 SSE 改为全局单连接

```ts
// src/composables/useJobStream.ts
export function useJobStream(projectName: Ref<string>) {
  const jobs = useJobsStore()
  let es: EventSource | null = null
  let retry = 0

  function connect() {
    es?.close()
    es = new EventSource(`/api/jobs/stream?project=${encodeURIComponent(projectName.value)}`)
    es.addEventListener('snapshot', e => { jobs.replaceAll(JSON.parse(e.data)); retry = 0 })
    es.addEventListener('job', e => {
      const job = JSON.parse(e.data)
      jobs.upsert(job)
      // 任务完成时只重载受影响的那个 shot，不要 reload 整个项目
      if (job.state === 'done' && job.shot_id) {
        useProjectStore().refreshShot(job.shot_id)
      }
    })
    es.onerror = () => {
      es?.close()
      // 指数退避重连，最长 30s
      setTimeout(connect, Math.min(30000, 1000 * 2 ** retry++))
    }
  }
  onMounted(connect)
  onUnmounted(() => es?.close())
}
```

**🔴 两条必须遵守的规则**：

1. **一个项目一条 SSE 连接。** 现在是「每任务一条」，20 个镜头 = 20 条连接，浏览器 6 连接上限会直接卡死。
2. **任务完成时只刷新受影响的 shot**（`GET /api/project/{p}/shot/{shot_id}`），不要 `loadProject()` 整个重载。20 个镜头的项目，每完成一个就全量重载，页面会疯狂闪烁。

## 4.9 「全部生成」的确认对话框

点顶栏「▶全部生成」时，**先调 `dry_run`，把结果摆给用户看，再让他确认**：

```
┌──────────────────────────────────────────┐
│ 确认批量生成                              │
├──────────────────────────────────────────┤
│ 将执行：                                  │
│   分镜图  6 个                            │
│   配音   12 个                            │
│   尾帧    4 个                            │
│   视频   18 个   ← 受 1 RPM 限制          │
│                                          │
│ 预计耗时：约 24 分钟                      │
│ 消耗配额：视频 96 秒 / 剩余 204 秒        │
│                                          │
│ ☑ 跳过已锁定的镜头                        │
│ ☑ 跳过已完成的产物                        │
│                                          │
│              [取消]  [开始生成]           │
└──────────────────────────────────────────┘
```

**配额不足时禁用「开始生成」并说明还差多少。** 让用户在提交前就知道，而不是跑到第 15 个才失败。

## 4.10 保留但简化的页面

### `/p/:name/script`（剧本编辑）
保留结构化编辑，但增加**「按场次/镜头」两级编辑**，与新数据模型对齐。保存后调 `POST /script`，后端做 diff 合并——**已生成的产物一律保留，不因剧本修改而清空**。

### `/p/:name/characters`（角色库）
保留三 Tab 生成 + 绑定。**必须新增：绑定时保存 Agnes 返回的公网 URL 到 `views[view].url`。** 这是分镜图图生图和一致性的地基，现在只存本地路径是不够的。

### `/settings`
必须真正接后端（现在只存本地 form）：
- Agnes API Key（写 `.env`，返回时脱敏）
- 代理地址
- **ImageHost 选择 + 配置**（阶段 1 新增，很重要）
- 默认画幅 / 尺寸档位 / 帧率
- 默认音色 / 语速
- 字幕样式
- **配额上限**（让用户按自己账号类型调整）
- 加一个「测试连通性」按钮，实际调一次 `/v1/chat/completions` 验证
