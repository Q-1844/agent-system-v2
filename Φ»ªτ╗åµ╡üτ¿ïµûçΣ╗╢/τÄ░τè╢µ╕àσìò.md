# 第二部分　数据结构现状

## 四层模型总览

真相源：`src/core/models.py`。磁盘文件：每个项目 `projects/{项目名}/output/project.json`（v2）。

```
Project
├── name: str
├── schema_version: int = 2
├── created_at / updated_at: float
├── style: StyleAnchor          ← 风格在这一层
├── characters: List[Character] ← 角色在这一层
└── scenes: List[Scene]         ← 场景在这一层
        └── shots: List[Shot]   ← 镜头嵌套在场景里（父子关系）
```

## 2. Character 层 — 三种来源

### 2.1 数据结构

`@dataclass Character`（models.py:219）：
```
name: str
description_en: str                    # 英文描述（生图提示词）
views: Dict[str, Asset]                # {"front": Asset, "side": Asset, "back": Asset}
```
`Asset`（models.py:28）：`local: str|None`（本地路径）、`url: str|None`（公网 URL，送 Agnes）、`status`、`error`、`updated_at`。

### 2.2 三种来源对比

| 来源 | 存储位置 | 数据结构 | 如何产生 | 与项目的关系 |
|------|----------|----------|----------|--------------|
| **① 剧本定义的角色** | `parsed_script.json`（v1）的 `characters[]` | `{name, description, reference_images?}` | script-editor 保存剧本时由 `ScriptParser` 从 YAML 写入 | 仅 name+description，**无图**。`migrate_v1_to_v2` 时变成 v2 `Character{name, description_en, views:{}}`（views 空） |
| **② Characters 页新增/出图的角色** | 前端 `store.characters`（内存）+ 角色页三视图缓存在 `store.characterCache` | `{name, description, reference_images:{}}`（前端 Character 接口） | 「+添加角色」本地 push；Tab 生成三视图存缓存 | 点「绑定到项目」才落盘：`bind` 接口把三视图存到 `output/characters/{name}_{view}.png` + 写 `parsed_script.json` 的 `reference_images` |
| **③ savedCharacters 角色库** | `saved_characters/{id}/` 目录 | `meta.json`：`{id, name, description, created_at, updated_at}`（**无 views**）+ 6 个 PNG 文件：`{front/side/back}_{raw/seg}.png` | 「保存到角色库」`POST /api/character/save` 写入 | 与项目**完全独立**。角色库项点击「加载」只把 name/desc/views 塞进前端内存缓存，**不自动落盘到项目**，需再点「绑定到项目」 |

### 2.3 三者的相互关联（现状）

- ① 和 ② 都往 `parsed_script.json` 写，但**格式不同**：① 是 `{name, description}`，② 绑定后是 `{name, description, reference_images:{front,side,back:路径}}`。
- ③ 角色库与项目**无任何外键关联**，纯靠 name 匹配（人工）。
- 🔴 **视图键名不统一**：磁盘上 `我的动画短片/project.json` 里 小星/暗影 的 views 键是 `front/side/**full**`（旧命名），而新绑定的 战斗机甲 用 `front/side/**back**`（新命名，阶段5做了 full→back 重命名但有兼容垫片）。`Character.ref_url()` 只认 `front/side/back`，遇到 `full` 会漏掉——靠 base64 兜底。
- 🔴 **角色库 vs 项目角色无同步**：在角色页改了项目角色的名/描述，角色库里同名角色不会跟着变；反之亦然。

## 3. Scene 层

`@dataclass Scene`（models.py:199）字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `scene_id` | str | "s01" |
| `title` | str | 场景标题 |
| `location` | str | 地点 |
| `time_of_day` | str | 时段 |
| `summary` | str | 摘要 |
| `shots` | List[Shot] | **镜头嵌套在场景里** |

🔴 **Scene 的 title/location/time_of_day/summary 四个字段，剧本编辑器完全不暴露**。script-editor 只编辑 v1 字段（description/camera/lighting/motion/dialogue/characters）；迁移时 `title=""`、`location=""`、`time_of_day=""`、`summary=description`。所以这四个 v2 字段对剧本创建的项目**永远是空/重复的**。

### 场景—镜头父子关系怎么存

**双向存储**：
1. **嵌套**：`Scene.shots: List[Shot]`——镜头作为子列表存在场景对象里（`models.py:205`，`Scene.to_dict` 序列化时 shots 是 scene 的子字段）。
2. **反向引用**：`Shot.scene_id: str`——每个镜头自己记着属于哪个场景（`models.py:153`）。

迁移时一个 v1 scene → 1 个 v2 Scene + 1 个 Shot（`shot_id="{scene_id}_c01"`，`scene_id` 回填）。`split-dialogue` 会在同场景内插入新 Shot 并重排 `shot_id`（`s01_c01`→`s01_c02`...），`split_next` 字段串起拆分链。

## 关键一：风格字段现在存在吗？在哪层？自由文本还是枚举？

**存在。在 Project 层。** 是 `StyleAnchor`（models.py:235）：

```python
@dataclass StyleAnchor:
    art_style: str = "anime, cinematic composition"   # 画风
    palette: str = ""                                  # 配色
    aspect_ratio: str = "16:9"                         # 画幅 16:9 / 9:16 / 1:1
    size_tier: str = "1K"                              # 固定 1K
    era: str = ""                                      # 时代
    extra: str = "high detail, consistent art style"   # 额外
```

- **全部自由文本（str），无枚举约束**。`aspect_ratio` 注释里写了 16:9/9:16/1:1 但代码不校验。
- `suffix()` 把 `art_style/palette/era/extra` 拼成后缀，所有 prompt 末尾统一拼接（`prompt_builder.py`），保证全片风格一致。
- 🔴 **画幅与尺寸实际不由用户控制**：
  - script-editor 的「尺寸」下拉（1152x768 等）→ v1 `project.size` → **迁移时被丢弃**，`aspect_ratio` 硬编码 "16:9"、`size_tier` 硬编码 "1K"。
  - Settings 页的 Style 输入框 → `store.style`（硬编码默认值，不随项目加载）→ 保存进 YAML `style:` → v1 `project.style` → 迁移成 `art_style`。**只有 art_style 这一项能从用户输入流到 v2，其余 StyleAnchor 字段用户根本碰不到。**
  - 视频生成尺寸由 `aspect_ratio` 决定（16:9 → 直提交 1280x704），与用户在 UI 选的"尺寸"无关。
- 真实磁盘值（`我的动画短片/project.json`）：`{art_style:"anime, soft lighting, cinematic composition", palette:"", aspect_ratio:"16:9", size_tier:"1K", era:"", extra:"high detail, consistent art style"}`。

## 关键二：双数据源断裂（重设计必须解决）

项目里存在**两份并行、会分裂的数据**：

| 文件 | 格式 | 谁写它 | 谁读它 |
|------|------|--------|--------|
| `output/parsed_script.json` | **v1**（`{project:{name,style,size}, characters:[{name,description,reference_images?}], scenes:[{id,description,camera,lighting,motion,dialogue,status,image_path?}]}`） | ① 剧本保存 `POST /script`　② 角色绑定 `bind`　③ 改名/改描述 `updateProjectCharacter` | 仅当 `project.json` **不存在**时，`ProjectStore.load()` 迁移它→v2 |
| `output/project.json` | **v2**（四层模型） | ① 首次 `load()` 时从 v1 迁移生成　② 之后所有 shot 级操作（`update_shot`/`split`/first_frame/video...）经 `ProjectStore.save()` 写它 | 所有 shot 级接口（`/shots`/`/shot/{id}/...`/`/orchestrate`/`/compose-shots`） |

🔴 **断裂机制**：`project.json` 一旦生成，`ProjectStore.load()` 就**只读 `project.json`，不再看 `parsed_script.json`**（store.py:116-117）。但**角色绑定/改名/剧本保存仍只写 `parsed_script.json`**。后果：
- 在 `project.json` 已存在的项目里，**新绑定的角色不会进 `project.json`** → 分镜生成的 `_shot_char_refs` 拿不到新角色参考图。
- 改剧本场景（新增场景/改台词）只更新 `parsed_script.json`，**`project.json` 的 scenes/shots 不变** → 分镜页看到的还是旧场景。
- 实测印证：`我的动画短片` 的 `parsed_script.json` 里角色是「战斗机甲」，但 `project.json` 里角色是「小星/暗影」——**两份已经分裂**。

> 这是"角色/场景改了但分镜页没变"类问题的根因。重设计时要么统一到单一数据源（v2 project.json），要么在每次写 v1 后同步重建 v2。

# 第三部分　重设计需注意的关键断层（汇总）

按影响排序，供设计决策参考：

1. **双数据源分裂**（第二节关键二）——角色绑定/剧本保存写 v1，管线读 v2，v2 存在后 v1 被无视。最严重。
2. **剧本编辑器只写不读**——无法回显已存剧本，每次打开是空表。
3. **角色页不加载项目角色**——`getProjectCharactersFull` 接口闲置，左侧列表永远空；角色散落三处无统一视图。
4. **配音无独立入口**——ShotCard 无配音按钮，`generateShotAudio`/`splitDialogue` 接口闲置；提示"去音频页"指向已删页面。配音只能靠编排器批量。
5. **风格/画幅用户不可控**——UI 的"尺寸"下拉被迁移丢弃，`aspect_ratio`/`size_tier` 硬编码；只有 `art_style` 能从用户流到 v2，且 store 默认值不随项目加载。
6. **Settings 页大面积死控件**——7 项设置填了不发送/后端不持久化。
7. **无"新建项目"入口**——`createProject` 接口闲置，只能靠 ShotBoard 下拉选已存在项目。
8. **视图键名 full/back 不统一**——旧角色 `full`，新角色 `back`，靠兼容垫片兜底。
9. **Scene 的 title/location/time_of_day/summary 字段无 UI 编辑入口**——v2 有字段但剧本编辑器不暴露，迁移后恒为空。
10. **TabSheet「+添加裁剪框」是空操作**——点了只弹 toast，实际框选靠 canvas 直接拖。

> 以上 10 条都不需要你在重设计里"修旧按钮"，而是决定**新流程里这些功能该不该保留、以什么形态存在**。例如配音入口（#4）和新流程"配音前置"的定位直接相关；风格/画幅（#5）和"项目建项目+风格画幅"步骤直接相关。
