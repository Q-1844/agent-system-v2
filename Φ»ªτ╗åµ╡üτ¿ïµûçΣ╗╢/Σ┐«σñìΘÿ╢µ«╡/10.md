
* 不 auto approve
* 不 auto regenerate

* 不创建新 Resources
* 不创建新 Scene entities

它只是：

> 当前 READY Binding 在当前 canonical truth 下的确定性 generation projection。

# 5. Pack Compile Gate

编译前必须调用现有 S3B.2 validity。

行为：

## Case A — UNBOUND

如果：

```text
readiness == UNBOUND
```

则：

```text
compile = BLOCKED
```

原因：

```text
binding_unbound
```

不得：

* 猜 binding
* 自动建 binding
* 使用 legacy generation files
* 使用旧 StyleAnchor
* 从 Shot 文本猜资源

---

## Case B — NOT_READY

如果：

```text
readiness == NOT_READY
```

则 Pack 编译必须拒绝。

必须保留 / 转发 S3B.2 structured validity issues。

例如：

```text
fingerprint_mismatch
look_not_approved
scene_instance_view_missing
stale_dependency
project_visual_profile_unspecified
...
```

不得自动 refresh。

不得：

```text
compile → refresh → compile
```

---

## Case C — READY

只有：

```text
readiness == READY
```

才允许进入 Pack Compiler。

这是硬 Gate。

Pack 必须说明：

> “我是基于哪一个 Binding 和哪一组当前 dependency basis 编译出来的。”

建议包含：

```text
binding_revision

dependency_fingerprints

visual_profile_fingerprint
```

如果当前 S3B.2 read model 已经有更合适的字段，复用。

目的：

* reproducibility
* debugging

* race detection
* future cache key foundation

但是：

> 这些字段只是 Pack provenance，不形成第二份 canonical truth。

不要写回 store。

# 8. Visual Profile projection

Pack 必须包含当前：

```text
ProjectVisualProfile
```

但保持 model-neutral。

例如可包含：

```text

其它当前 canonical semantic fields
visual_profile_fingerprint
```

不要生成：

```text
"cinematic anime masterpiece, 8k..."
```

这属于未来 Prompt / Provider Adapter。

Pack 存：

```text
semantic style
```

而不是：

```text
provider prompt fragment
```

理论上 validity 已经 NOT_READY。

如果在 compile race 中发现 unspecified：

# 9. Scene projection

```text

```

```text
SceneInstance identity

```

但是：

不要重新计算 visibility projection。

不要把整个 SceneState 粗暴塞进 Pack。

应消费 Scene System 已经定义好的：

```text
view-relevant scene truth
```

如果 SceneInstanceView 本身已有稳定语义描述 / approved basis，可引用。

# 10. Scene visual reference

Pack 必须能够表达：

> “这个 Shot 的环境视觉参考来自哪一个 approved SceneInstanceView。”

但是 S3B.3 不负责真正读取图片 bytes。

优先保存：

```text
source entity ID
stable asset ID / existing reference handle
semantic purpose
```

如果 SceneInstanceView 当前没有统一 `ReferenceAsset ID`：

不要创造跨域复制。

可以保留：

```text
scene_instance_view_id
```

让未来 adapter 再通过 Scene System resolve media。

不要为了方便把：

```text
/tmp/xxx.png
```

变成 Pack 的 canonical identity。

# 11. Character projection

对于 Shot 中每一个角色：

使用：

```text
Shot.characters
```

作为确定性角色顺序。

不要使用：

* dict iteration
* resource store insertion order
* alphabetical order

除非当前 canonical 明确定义其它顺序。

每个 Character Pack Entry 至少表达：

```text
character_name
look_id
composition_id optional
semantic appearance
reference sources
effective visual relations
```

不要复制整个 Character database。

只投影当前 Shot 真正需要的字段。

# 12. Character reference precedence

默认语义：

## 没有 Composition

角色视觉主要来自：

```text
CharacterLook approved reference
```

它是：

```text
character appearance primary evidence
```

Character identity reference 如存在，可以作为 supporting evidence。

---

## 有 Composition

Composition 可以成为更强的：

```text
character + look + relation
```

视觉证据。

但注意：

> Composition 不是无条件永远 primary。

必须先检查它是否与当前 Shot Action 的 temporal state 冲突。

> direct `prop_bindings` 是否需要可选 `character_name` 是尚未裁决的议案。


> 当前 canonical 已经有明确等价字段。

# 17. Direct Prop subject resolution V1

如果 Pack 需要知道：

```text
这个 Prop 属于哪个 Character
```

只能从已有 explicit semantics 确定。

允许：

### Rule 1

如果 action 明确：

```text
action.prop_id == prop_id
action.subject_character != None
```

则：

```text
prop action subject = action.subject_character
```

---

### Rule 2

如果 Composition 明确表达：

```text
Character + Prop + relation
```

则 Composition 自己已经给出 subject。

但这种 Prop 不应该再作为 direct duplicate binding。

---

### Rule 3

如果 relation 明显属于：

```text
scene/world relation
```

而不是：

```text
character body relation
```

则不要求 character owner。

前提是当前 vocabulary 本身能明确区分。

不要自行猜 vocabulary。

---

### Rule 4

如果：

```text
multiple characters
+
character-local prop relation
+
没有 explicit subject
```

则：

```text
Pack compilation BLOCKED
```

reason：

```text
prop_subject_ambiguous
```

或等价明确错误码。

---

### Rule 5

不要因为：

```text
“看起来只有 Alice 最合理”
```

就猜 Alice。

---

### Rule 6

对于只有一个角色的 Shot：

如果当前 relation vocabulary 能明确证明这是 character-local relation，可以允许：

```text
single-cast deterministic resolution
```

但必须：

* 明确写测试
* 明确写在 report
* 不写回 canonical binding
* 不改变 binding intent

如果无法从 vocabulary 安全判断是否 character-local：

仍 fail closed。

---

# 18. Composition 与 direct Prop 的关系

继续遵守 S3B.1：

```text
Composition-covered Prop
```

不能再出现：

```text
direct PropBinding
```

作为第二个 effective visual relation source。

Pack 编译时必须再次 defensive check。

如果发现：

```text
same Prop
+
Composition relation
+
direct PropBinding relation
```

则：

```text
BLOCKED
reason = binding_conflict
```

不得“选一个比较好”。

---

# 19. Composition 可以引用 Prop standalone image，但不能产生第二套 relation truth

例如：

```text
Composition:
Alice + Sword @ right_hand
```

Pack 可以：

* 用 Composition 作为 spatial/character relation evidence
* 用 Sword approved standalone reference 作为 `prop_identity` supporting evidence

但 standalone Prop reference：

```text
不能再次声明 Sword@right_hand
```

否则形成两套关系真相。

原则：

```text
Composition owns relation.
Prop reference may support identity.
```

---

# 20. 多个 Composition 覆盖同一个 Prop

不要只检查：

```text
Composition vs direct Prop
```

也要 defensive 检查：

```text
Composition A
Composition B
```

是否对同一个实体产生两个同时生效的 spatial relation truth。

如果两个角色 Composition 同时都显示：

```text
same Sword held
```

一般情况下应 fail closed：

```text
multiple_effective_prop_relations
```

或等价 structured issue。

唯一例外：

> 当前 Action 的 explicit temporal semantics 足够把两者明确分到不同时间阶段。

例如未来的：

```text
hand_off
```

如果能严格证明：

```text
Composition A = start
Composition B = end
```

则它们不是“同时生效”。

如果不能严格证明：

fail closed。

# 22. Action-aware reference planning

这是 S3B.3 最重要的逻辑之一。

---

## 22.1 none / static

正常情况下：

```text
Composition
```

可以作为 character primary reference。

Direct Prop relation 可以作为 static relation。

temporal_scope：

```text
static
```

或：

```text
throughout
```

---

# 23. pick_up

例：

```text
Alice starts empty-handed
Alice picks up pistol
Alice ends holding pistol
```

如果 Composition 是：

```text
Alice + Pistol @ right_hand
```

则：

**禁止**把这个 Composition 当成 first/start-state primary reference。

因为它会向生成模型错误暗示：

```text
第一帧 Alice 已经拿着枪。
```

正确行为：

```text
CharacterLook
→ start / primary character evidence

Pistol standalone reference
→ prop identity supporting evidence

Alice + Pistol Composition
→ end-state evidence
```

即：

```text
composition.temporal_scope = end
```

或等价语义。

这是硬测试。

---

# 24. put_down

例：

```text
Alice starts holding pistol
Alice puts pistol down
Alice ends empty-handed
```

如果 Composition：

```text
Alice + Pistol @ right_hand
```

则它应该是：

```text
start-state evidence
```

而不是 end-state evidence。

角色 Look 可以继续支持 end appearance。

---

# 25. hand_off

V1 Action schema 当前只有：

```text
subject_character
prop_id
```

不一定有：

```text
target_character
```

所以禁止偷偷猜 recipient。

允许：

如果 canonical visual evidence 本身明确提供：

```text
subject-character Composition with Prop
+
another character Composition with same Prop
```

且能够唯一、无歧义地映射成：

```text
start holder
end holder
```

可以 temporal classify。

否则：

```text
action_target_unspecified
```

或：

```text
action_semantics_ambiguous
```

并 BLOCK pack compile。

不要根据：

```text
“Shot 中只有另一个人”
```

默认把对方当 receiver，除非你明确把这一行为作为严格 deterministic V1 policy，并证明不会篡改 intent。

安全优先：

> fail closed 优于 guess。

---

# 26. custom Action

可以保留：


作为 semantic action metadata。

只有 explicit structured information 才参与 reference temporal classification。

不调用 LLM。

# 27. Pack compile diagnostics

除了 Binding Validity issues，本阶段允许 Pack 自己产生：

```text
PackCompileIssue
```

因为：

```text
READY Binding
```

只表示：

```text
dependencies valid + fresh
```

不意味着：

```text
所有 generation reference semantics 一定无歧义
```

Pack-level issue 示例：

```text
prop_subject_ambiguous
multiple_effective_prop_relations
action_target_unspecified
temporal_reference_conflict
reference_asset_unresolvable
dependency_changed_during_compile
```

这些：

* 是 derived diagnostics
* 不写回 Binding
* 不把 Binding 改成 NOT_READY
* 不修改 canonical

建议返回：

```text
COMPILED
```

或者：

```text
BLOCKED
```

不要发明持久化 pack status。

# 29. Reference Asset resolution

所有 Resource references 必须通过现有 canonical / service helper 获取。

不要：

* 扫目录找图片
* 按文件名猜 asset
* 取最新文件
* 从 output folder 自动发现
* 从旧 generation result 猜 reference
* 直接 glob png

必须通过：

```text
approved canonical references
```

如果：

```text
approved ID 存在
但实际 ReferenceAsset 无法 resolve
```

则 fail closed。

---

# 30. 不要把 raw image path 当 semantic identity

Pack 中优先使用：

```text
reference_asset_id
source entity ID
scene_instance_view_id
```

而不是：

```text
/path/to/image.png
```

如果未来 provider 需要真实文件路径：

由 Generation Adapter resolve。

S3B.3 不应该把路径提升为 production truth。

---

# 31. Deterministic ordering

相同 canonical state：

```text
compile N 次
```

结果必须一致。

不得依赖：

* set iteration
* unordered dict
* filesystem ordering
* timestamps
* random UUID
* current time

Pack 本身不要带：

```text
compiled_at = now()
```

除非项目已有严格需要。

推荐不要有时间戳。

---

# 32. Character order

Pack characters 顺序必须稳定。

优先：

```text
Shot.characters canonical order
```

然后按该顺序投影 CharacterBinding。

Binding 自身顺序不能覆盖 creative Shot order，除非当前 schema 明确规定。

---

# 33. Prop order

保持：

```text
binding.prop_bindings
```

当前语义顺序，或者明确 deterministic canonical order。

不要 alphabetical sort，除非项目已有规定。

但这只是：

```text

```

# 37. Concurrency / TOCTOU 一致性

这个阶段必须认真处理一个问题：

```text
validity READY
→ 开始 compile
→ dependency 正好被另一个操作修改
→ pack 混入两个不同时间点的数据
```

禁止输出 mixed-state Pack。

实现一个 fail-closed consistency guard。

推荐逻辑：

```text
1. pre_validity = read_validity()
2. require READY
3. materialize pack dependencies
4. build candidate pack
5. post_validity = read_validity()
6. compare consistency basis
```

至少比较：

```text
binding_revision
binding document revision
resolved SIV id
readiness
actual dependency fingerprint basis
visual profile fingerprint
```

具体复用 S3B.2 已暴露字段。

如果 pre/post 不一致：

```text
BLOCK
dependency_changed_during_compile
```

不要：

* 自动重试无限循环
* 自动 refresh
* 静默使用旧 pack

如果当前 architecture 有更可靠的 snapshot/locking 机制，可以使用。

但不要创造粗粒度 global write lock 破坏现有并发设计，除非确有必要且有测试证明。
