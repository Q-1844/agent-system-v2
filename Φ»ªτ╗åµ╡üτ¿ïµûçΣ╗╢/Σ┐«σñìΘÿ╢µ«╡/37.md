# 1. 先修复两个实验可信度 BLOCKER

在继续大规模真实生成前，先处理：

## 1.1 Shot 字段变化后的 video prompt 自动同步

当前已经实证：

`update_shot_fields`

修改影响 video prompt 的字段以后：

`prompt_en / video prompt`

可能仍然保持旧文本。

这会直接污染所有校准实验。

必须调查当前真实生成链。

建立一个单一、可靠的 mutation 路径：

```text
修改影响生成语义的 Shot 字段
→ 自动 invalidate/rebuild 对应 video prompt
→ 保存
→ receipt 中明确记录
```

不要继续依赖执行者“记得再手工调用一次 prompt generate”。

必须保留 override 语义。

不得破坏 legacy/unbound 行为。

补 deterministic tests。

---

## 1.2 JobQueue 错误必须保留真实异常类型

当前：

`httpcore.ReadError`

等异常可能得到空 `str(e)`。

必须保证最终至少保存：

```text
exception_class
stage
message
provider
model
```

如果 message 为空：

不得返回空错误。

至少返回异常类名。

本项只改善可观测性，不改变 provider retry/fallback 行为。

# 5. 继续当前三档 Calibration Protocol

保持当前协议：

## NONE

实际尾帧与预期状态足够一致。

```text
→ 不修改故事
→ 正常进入下一镜
```

## MINOR

故事仍在轨道上，但：

* 朝向；
* 姿态；
* 位置；
* 动作阶段；
* 构图状态；

存在能够自然吸收的小偏离。

```text
→ 不重生成上一镜
→ 下一镜增加自然过渡动作
→ prompt 正式重建
→ 继续
```

## MAJOR

实际结果已经无法自然进入原计划下一镜。

例如：

* 错过关键动作；
* 人物处于完全不同状态；
* 道具关系改变；
* 叙事状态发生明显偏离；
* 下一镜直接执行会产生跳跃。

此时：

```text
→ 不立即简单重试
→ 尝试插入一个最小故事 beat
→ 将状态自然拉回主线
→ 必要时新增 Shot
→ 必要时新建真正的新故事段
→ prompt rebuild
→ binding refresh
→ 继续
```

但是：

# 不得为了制造样本而人为判成 MAJOR。

如果完整故事自然没有出现 major deviation：

如实记录。

随后增加高风险 Shot stress cases，而不是伪造失败。

# 6. “重试”与“顺势接故事”必须区分

本轮需要开始统计：

什么情况适合：

```text
retry current shot
```

什么情况适合：

```text
accept result + calibrate next shot
```

不要预先定义最终规则。

但每一次人工选择必须写原因。

重点研究：

* 身份严重损坏；
* 场景完全错误；
* 技术生成失败；

是否更适合 retry。

而：

* 姿态不同；
* 动作提前/延后；
* 位置略偏；
* 镜头自然落在意外但可用状态；

是否更适合 accept + adapt。

未来 Agent 很可能需要的不只是：

```text
none/minor/major
```

还会需要：

```text
accept_and_continue
accept_and_bridge
insert_story_beat
retry_generation
break_chain_and_reanchor
```

但本阶段不要提前写死。

从真实数据中归纳。

# 7. 时长继续作为实验变量

现有实测已经表明：

动态 Shot 过短容易在动作中间停住。

本阶段继续记录：

```text
5s
8s
10s
```

对：

* 动作完整度；
* 尾帧稳定性；
* 下一镜可接性；
* 运镜；
* 多余动作；
* 节奏；

的实际影响。

不要默认“越长越好”。

最终寻找：

```text
shot type
→ recommended duration range
```

而不是全局固定秒数。
