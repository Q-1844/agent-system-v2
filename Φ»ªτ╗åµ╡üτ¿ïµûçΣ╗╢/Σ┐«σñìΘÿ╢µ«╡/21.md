# 3. 第一项：修正 Visual BOUND routing predicate

B1 已暴露：

```text

```

附着于 `ShotProductionBinding` 后，即使没有完整视觉 binding，也可能影响：

```text
shot_has_binding()
```

从而把 Shot 错误路由到 BOUND。

必须重新明确两个概念：

```text
binding metadata exists
```

不等于：

```text
valid visual production binding exists
```

实现或重构一个明确 predicate，例如：

```text
has_visual_production_binding(...)
```

名字可按仓库风格调整。

只有真正满足 Visual V1 BOUND 要求的 binding 才：

```text
→ BOUND
```

仅存在：

```text
dialogue_speaker_binding
未来其他非视觉 metadata
```

不得改变 BOUND / UNBOUND 路由。

要求 targeted tests 锁死。

# 14. 第六项：正式实现 NativeAVFreshness

建立纯派生：

```text
NativeAVFreshness
```

至少：

```text
CURRENT
STALE
UNTRACKED_LEGACY
MISSING
```

## CURRENT

当前 final VideoVersion：

```text
stored generation_basis
==
recomputed current generation_basis
```

## STALE

例如：

```text
dialogue changed
speaker map changed
spoken language changed
visual basis changed
provider changed
model changed
provider options changed
compiler schema changed
```

## UNTRACKED_LEGACY

旧：

```text
generation_basis={}
```

不应直接判为 STALE。

含义：

> 视频仍然合法存在，但系统无法证明它对应当前 Native AV generation facts。

## MISSING

不存在 selected/final video。

# 16. 第七项：补齐 long-running generation race guard

Native AV generation 过程中可能发生：

```text
dialogue change
speaker binding change
language change
visual binding change
```

不能：

```text
开始生成时基于旧状态
→ 几分钟后直接 attach
→ 冒充符合当前 project
```

实现三阶段：

## Phase 1

```text
read
validate
build NativeAVGenerationPack
snapshot generation_basis
```

短事务。

## Phase 2

```text
Agnes generation
```

不持 project lock。

## Phase 3

provider 完成后：

```text
recompute generation_basis
compare
```

相同：

```text
commit VideoVersion
```

不同：

```text
dependency_changed_before_commit
```

不得把该版本 attach 为 CURRENT production version。

provider result 可保留为 evidence/diagnostic。

不得 import A2 `av_sync` 来实现。

复用设计哲学，不复用被冻结模块本身。
