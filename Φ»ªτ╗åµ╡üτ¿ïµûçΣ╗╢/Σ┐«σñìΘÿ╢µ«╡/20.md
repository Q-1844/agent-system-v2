# Native AV C1 — Controlled Native AV Production Foundation

## 0. 当前基线与本阶段性质

当前已经完成并人工验收：

```text
NATIVE AV B1 — Dialogue + Speaker Control
B1 FINAL PASS
```

真实证据：

```text
A 侧（原生产方式）
- dialogue 样本 4/6 FAIL
- 出现错误语言（日语）
- 出现把 motion / visual instruction 当台词朗读
- 存在随机背景音乐

B 侧（Controlled Dialogue）
- dialogue 6/6 PASS
- 多角色三句对白 3/3 PASS
- speaker swap = 0
- lip-sync 全部可用
- 无视觉负面反馈
```

因此本阶段不再进行“Native AV 是否值得做”的能力验证。

本阶段性质正式升级为：

> **Production Foundation。**

目标：

> **把 B1 已经被真实人耳/人眼证明有效的 Controlled Native AV，从实验性 query flag 升级为现有 Shot Video Production 的正式默认能力，并补齐生产系统必须具备的 provenance、freshness、race safety、BOUND/UNBOUND 一致性以及 AV prompt 编译。**

同时开始把：

```text
visual staging
+
dialogue
+
speaker
+
shot-local sound intent
```

编译为一个协调的 Native AV performance request。

# 4. 第一项必须先修：Binding metadata ≠ Visual BOUND routing

B1 已经发现一个结构性问题：

```text
ShotProductionBinding
```

现在只要存在某些 binding metadata，就可能使：

```text
shot_has_binding(...)
```

把 Shot 路由到 BOUND video path。

这导致：

```text
只有 dialogue_speaker_binding
但没有完整 visual binding
```

的 Shot 也可能误入 BOUND，然后失败。

Productionization 前必须把概念拆清。

至少区分：

```text
has_binding_metadata
```

和：

```text
has_visual_production_binding
```

或者实现等价语义。

视频路由：

```text
BOUND / UNBOUND
```

只能由：

> **完整、有效的 Visual Production Binding**

决定。

以下字段存在本身不得改变 Visual routing：

```text
dialogue_speaker_binding
audio_event_intent
Native AV metadata
```

要求测试锁死：

```text
dialogue-only metadata
→ 不改变原 visual route

audio-only metadata
→ 不改变原 visual route

valid visual binding
→ BOUND

no valid visual binding
→ UNBOUND
```

```text
NativeAVGenerationPack
```

```text
derived
ephemeral
deterministic
provider-neutral
无 business ID
不持久化
```

建议结构：

```text
schema:
    native_av_generation_pack_v1

    shot_id
    scene_id

    route                         # BOUND | UNBOUND
    existing_visual_projection
    visual_basis_fingerprint
    visual_reference_identity

    dialogue_id

    schema
```


形成第二套视觉系统。

# 9. Production hardening：spoken text 与 stage direction 分离

B1 已经确认现有真实数据中存在：

```text
（舞台指示）
```

并且 B1 parser 当前会保留它。

Production 阶段必须解决。

目标是：

> **只有真正应该从角色嘴里说出来的文字能够进入 Spoken Dialogue block。**

至少支持以下确定性情况。

## Case A — 独立舞台指示行

```text
（林晚星转过身）
```

或：

```text
(Gu Yan pauses)
```

归类为：

```text
non_spoken_direction
```

绝不作为对白朗读。

如果其内容适合作为 performance hint：

允许送到 non-spoken performance block。

---

## Case B — speaker + delivery cue + spoken text

例如：

```text
林晚星：（低声）别过去。
```

如果规则能够确定性解析：

```text
speaker = 林晚星
delivery_hint = 低声
spoken_text = 别过去。
```

`低声` 不得进入 spoken text。

---

## Case C — 无法唯一理解的 markup

不要调用 LLM 猜。

返回：

```text
ambiguous_dialogue_markup
```

并 fail closed，或者在规格明确允许的情况下结构化 warning 后拒绝 dispatch。

不得：

> “大概是这个意思，所以继续烧视频。”

# 11. Native AV Prompt Compiler V1

不要继续把当前实现永久停留在：

```text
visual prompt
+
dialogue block append
```

本阶段建立正式：

```text
NativeAVPromptCompiler
schema = native_av_prompt_v1
```

它仍然可以输出 Agnes 已验证有效的单行 prompt。

这里的“Compiler”指的是：

> **明确分层组织已有项目事实。**

不是建立巨大 prompt framework。

---

# 12. Prompt Compiler V1 必须隔离四类语义

内部至少区分：

```text
VISUAL / PERFORMANCE
NON-SPOKEN ACTION
SPOKEN DIALOGUE
NATIVE SOUND ENVIRONMENT
```

最终 Agnes prompt 可以合并成一条文本。

但编译前不能把四者混成一段自由文本。

---

# 13. Compiler invariant 1：只有 Dialogue 可以被朗读

B1 已经观察到：

> 原路径把 motion prompt「它微微点头，转身欲行」直接念了出来。

因此每个含 dialogue 的 prompt 必须具有等价于：

```text
Only the explicitly assigned dialogue is spoken aloud.
Do not speak, narrate, or read any visual description,
camera instruction, action instruction, motion description,
sound instruction, or production note.
```

的明确语义。

具体英文可以根据真实 Agnes probe 经验调整。

但这个规则必须成为：

```text
compiler invariant
```

而不是某个测试 sample 的临时 patch。

---

# 14. Compiler invariant 2：台词内容不可改写

告诉 provider：

```text
Speak the supplied dialogue exactly.
Do not translate it.
Do not paraphrase it.
Do not invent additional spoken dialogue.
```

但不要过度限制自然表演。

允许：

```text
breathing
natural pauses
non-lexical performance sounds
```

前提是：

> 不新增具有剧情含义的台词。

---

# 15. Compiler invariant 3：Speaker assignment 明确

多人 Shot 必须明确编译：

```text
line 1 → A
line 2 → B
line 3 → A
```

同时表达：

```text
Do not swap the speakers.
```

如果某在场人物本镜不说话：

```text
Character X remains silent in this shot.
```

B1 已经证明这一类控制有效。

继续沿用，而不是重新设计 speaker 技术。

---

# 16. Compiler invariant 4：Language 明确

凡有 dialogue：

prompt 必须明确：

```text
spoken language = <project spoken language>
```

不要依赖名字、画风或文本形状让模型自行判断。

特别继续防护此前真实观察到的：

```text
动画风 + 短句 → 日语先验
```

---

# 17. 开始真正利用 Native AV 的优势：动作和声音共同设计

这里是本阶段从“对白控制”进一步走向“Native AV 创作”的核心。

不要把：

```text
visual prompt
```

和：

```text
audio prompt
```

设计成互不相关的两个段落。

如果 canonical 已有：

```text
opening_state
end_state
motion
action_sequence
environment_motion
```

则 compiler 应保持其真实时序，让音频事件与动作关系能够被 Agnes 理解。

例如 canonical 表达：

```text
走到门边
→ 推开门
→ 停下
→ 说台词
```

prompt 应保持这种表演顺序。

不要变成：

```text
一大段画面描述
+
孤立对白
+
一大段音效关键词
```

Native AV 的优势就是：

> **同一次 generation 对动作、表演、口型和声音做共同解释。**

但不得发明 canonical 中不存在的动作。

# 18. 正式增加最小 Shot-local Audio Event Intent

允许在：

```text
ShotProductionBinding
```

增加可选：

```text
audio_event_intent
```

保持非常薄。

推荐：

```text
AudioEventIntent:
    music_policy: "none" | "allow_native"
    directives: List[str]
```

`directives` 只表达叙事上重要、与当前 Shot 动作绑定的声音，例如：

```text
rusty door creaks as it opens
two footsteps stop before the dialogue
soft rain outside the window
metal object hits the floor
cloth rustles as the character turns
```

不要建立：

```text
SFX ID
SFX Version
SFX library
AudioStem
AmbienceTrack
Audio timeline
```

Agnes 自己生成实际声音。

---

# 19. Audio Event Intent 默认可以为空

特别重要：

Agnes 已经被实验证明很擅长：

```text
SFX
ambience
动作同步声音
```

所以：

```text
audio_event_intent = empty
```

是正常状态。

系统不得要求 Director：

> 每个脚步、每件衣服、每次呼吸都填写音效。

只有：

> **这个声音对叙事或节奏有明确价值**

时才写 intent。

其余继续让 Agnes 自己判断。

# 20. Background Music production policy

B1 人评再次发现随机 BGM。

由于正式电影配乐未来属于 sequence-level Audio Post，因此 Native AV Shot 默认不应自行决定 score。

正式定义：

```text
music_policy = "none"
```

为 Native AV production 默认。

prompt 应表达等价于：

```text
No background music or musical score.
Use natural dialogue, diegetic sounds,
and appropriate environmental ambience only.
```

注意：

```text
no music
≠
silent background
```

必须允许：

```text
room tone
rain
wind
traffic
mechanical ambience
footsteps
door sounds
object sounds
```

---

# 21. `allow_native` 只是例外

如果某个特殊镜头确实要求：

```text
角色现场唱歌
电视里播放音乐
剧情内音源
极特殊创作实验
```

允许显式：

```text
music_policy = "allow_native"
```

但不要把它当正式全片配乐系统。

未来：

```text
score / motif / cross-shot music
```

仍属于 Sequence Audio Post。

# 22. Director 正式获得 Native AV planning discipline

现在 Native AV 已经是正式方向，因此允许修改 Director system prompt。

只修改：

```text
创作与数据填写规约
```

不要改：

```text
Director Runtime
tool loop
Scene Sub-Agent architecture
OCC
governance
```

Director 新增以下纪律。

---

## Dialogue discipline

`Shot.dialogue` 只保存：

> **真正应该从角色嘴里说出的文字。**

禁止把：

```text
镜头说明
动作说明
音效说明
摄影说明
```

混进 dialogue。

---

## Multi-speaker discipline

多角色对白尽量使用：

```text
角色名：「台词」
```

例如：

```text
林晚星：「门开了吗？」
顾岩：「还没有。」
```

不要生成：

```text
「门开了吗？」
「还没有。」
```

然后把 speaker 判断留给下游。

---

## Performance discipline

一句对白与动作有明确关系时：

让：

```text
action_sequence
```

表达其自然顺序。

例如：

```text
顾岩走到门边 → 推门 → 停顿 → 说话
```

而不是同时堆叠大量无法在一个短 Shot 内完成的行为。

---

## Native sound discipline

只有重要声音事件才进入：

```text
audio_event_intent
```

不要填充琐碎拟音。

---

## Multi-speaker staging

不要技术性禁止多人对白镜。

但如果：

```text
Shot 很短
+
多人连续轮流大量讲话
+
没有明确镜头语言价值
```

Director 应优先用更自然的电影切分。

这是：

```text
创作质量原则
```

而不是 provider hack。

---

# 23. 不改变 Script Writer ownership

Script Writer 继续拥有：

```text
故事
角色动机
对白内容
叙事
```

Director 不因为 Native AV 获得“随意重写对白”的权力。

Director 负责：

```text
把既有对白落进 Shot
speaker assignment
performance staging
shot-local sound staging
```

保持现有 ownership 边界。

# 28. Prompt compiler schema 必须进入 basis


因此 compiler schema 变化：

```text

```

但是：

```text

```

```text

```

不要粗暴把整串 prompt 当 canonical dependency。

# 29. 正式建立 Native AV Freshness

实现 derived：

```text
NativeAVFreshness
```

最少状态：

```text
CURRENT
STALE
UNTRACKED_LEGACY
MISSING
```

---

## CURRENT

selected/final VideoVersion 有 generation basis：

```text
stored basis == recomputed current basis
```

---

## STALE

任何 actual dependency 改变，例如：

```text
dialogue changed
speaker mapping changed
spoken language changed
audio event intent changed
music policy changed
visual binding/basis changed
provider changed
model changed
provider option changed
prompt compiler schema changed
```

---

## UNTRACKED_LEGACY

旧视频：

```text
generation_basis={}
```

不要自动标：

```text
STALE
```

旧视频仍然可以：

```text
显示
播放
手动选择
继续存在
```

只是系统诚实告诉用户：

> freshness 无法证明。

---

## MISSING

没有 selected/final video。

# 30. No Auto Regeneration

# 31. Provider 长任务 race guard

Native AV generation 是长任务。

从 provider dispatch 到完成期间可能发生：

```text
dialogue 修改
speaker binding 修改
spoken language 修改
audio intent 修改
visual binding 修改
```

因此：

## Phase 1

短事务：

```text
read
validate
build pack
snapshot generation basis
```

## Phase 2

无项目锁：

```text
provider generation
```

绝不能几十秒/几分钟持 project lock。

## Phase 3

provider 完成后短事务：

```text
recompute current basis
compare with dispatch snapshot
```

如果变了：

```text
dependency_changed_before_commit
```

provider 输出可保留为：

```text
evidence / diagnostics
```

但不得：

```text
attach as CURRENT VideoVersion
自动 final
冒充符合当前 canonical
```

尽量复用仓库已有 race-guard 设计哲学。

不要复制 A2 模块或 import `av_sync`。

# 48. 最终工程原则

> “给视频添加声音。”

> **“项目中的创作事实，有没有被完整、确定、无歧义地编译给一个能够同时生成画面与声音的模型？”**

系统负责明确：

```text
谁出现
做什么
谁说话
具体说什么
使用什么语言
谁保持沉默
哪个动作声音重要
是否禁止音乐
视觉身份和镜头状态是什么
```

Agnes 负责完成：

```text
picture
performance
voice realization
lip movement
breath
action-synchronized SFX
local ambience
```

最终仍然只有：

```text
VideoVersion
```

这一份完整的 Shot 媒体结果。

> **把已经验证正确的方向工程化做扎实。**

不是：

> **把所有未来可能需要的声音能力一次性实现。**

凡是已经有真实证据的问题：

```text

```

凡是还没有真实问题的问题：

```text
继续不做
```

这是 C1 的边界。
