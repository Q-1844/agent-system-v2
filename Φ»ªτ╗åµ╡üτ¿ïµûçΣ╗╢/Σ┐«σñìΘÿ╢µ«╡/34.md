# 2. Calibration 结论正式冻结

以下结论本轮不得重新实验：

## Reference

正式视频生产：

`R3 — Cinematic Identity Reference`

作为动物角色 reference format。

不要重新比较：

* R0
* R1
* R2
* R3

不要直接拿白底 Character Plate 作为正式视频 reference。

不要直接拿 Neutral Reference 作为正式视频 reference。

白底 Character Plate 可以继续作为上游 Character identity source。

如果正式系统需要：

Character Plate
→ i2i
→ Cinematic Identity Reference

这是允许的，而且是推荐路径。

但最终进入视频生成的动物身份参考应遵循 R3 已验证格式。

---

## Prompt

视频 prompt 使用：

`P1 minimal intent ~ base`

信息密度。

保持 calibration 中已经验证过的固定 style line。

Shot prompt 重点写：

* 本镜核心动作；
* 必要的动作方向；
* 必要的 camera intent；
* 极少量场景事实。

不要重新大段重复：

* 毛色；
* 身材；
* 耳朵；
* 尾巴；
* Location 全部细节；
* Look 全部细节；
* 十几条 negative constraints。

这些应该主要来自正式 production truth 和 references。

---

## 禁止重新启用 P3 思路

尤其禁止因为出现一次问题以后立刻追加：

`MUST`
`NEVER`
`STRICTLY`
`ABSOLUTELY`
`throughout the entire shot`

之类越来越重的定向约束。

上一轮已经证明：

针对葡萄增加硬约束可能引发更严重的物体删除副作用。

Production fallback 优先是：

`variant regeneration + selection`

其次才是：

`shot staging / composition adjustment`

而不是 prompt 无限膨胀。

# 6. 故事规格

作品：

# 《狐狸和葡萄》

目标：

极简、完整、无复杂支线的小型寓言。

主要元素严格控制为：

* 1 只主狐狸；
* 1 个主要 Location：葡萄园；
* 1 个核心视觉对象：葡萄；
* 无第二个主要动物角色；
* 无复杂人类角色；
* 无战斗；
* 无复杂抓取；
* 无多人对白；
* 无口型依赖。

故事核心保持经典结构：

狐狸进入葡萄园
→ 发现葡萄
→ 产生欲望
→ 观察 / 蓄力
→ 跳跃失败
→ 情绪反应
→ 自我安慰 / 转身离去
→ 葡萄仍在那里

不要为了“让故事丰富”增加：

* 第二只狐狸；
* 乌鸦；
* 农夫；
* 狗；
* 篱笆追逐；
* 多次复杂跳跃；
* 葡萄被摘下；
* 狐狸真的吃到葡萄。

本 Pilot 的价值恰恰来自：

**变量少。**

# 8. Fox Character

Resource Agent 创建正式狐狸 Character。

要求：

* 四足 animal fox；
* 不做人形化双足角色；
* 不穿复杂服装；
* 不加帽子 / 披风 / 武器 / 饰品堆；
* 身体比例清楚；
* 尾巴明显；
* 毛色结构简单稳定；
* 面部具有一定表达能力。

保持一个非常轻量的 identity anchor。

如果 calibration 中正式狐狸已经使用：

`左耳轻微缺口`

并证明有效，可以继续使用。

不要再加第二、第三个高强度身份标记。

目标不是：

“设计一只信息量爆炸的狐狸”。

而是：

> 设计一只能在 8 个镜头中稳定保持身份的动画狐狸。

---

# 9. 正式 Cinematic Identity Reference

Resource Agent / 现有正式 production pipeline 应为狐狸准备：

`Cinematic Identity Reference`

要求继承上一阶段 R3 原则：

* 同一只狐狸；
* 单主体；
* 狐狸完整可见；
* 自然四足姿态；
* 无强动作；
* 正常电影光线；
* 简化自然环境；
* 无白底；
* 无三视图拼版；
* 无文字；
* 无其他角色；
* 环境不抢主体。

最好让环境视觉语言与本项目葡萄园兼容。

但它仍然首先承担：

`fox identity`

而不是成为某一个具体 Shot 的构图模板。

必须保存：

* source identity provenance；
* i2i / generation basis；
* model；
* prompt；
* resulting ReferenceAsset；
* approval/review status。

禁止偷偷直接复用一个未登记 provenance 的测试图片。

如果允许正式注册 calibration 的 R3 资产，也必须通过当前 ReferenceAsset / provenance contract。

# 10. Vineyard Scene Production

Scene Agent 正式创建葡萄园生产事实。

尽量只创建：

`1 reusable Location`

然后根据 Story Scene 建立所需 SceneInstance / SceneState。

保持：

* 时间基本一致；
* 天气一致；
* 光线一致；
* 葡萄藤结构一致；
* 地形一致；
* 路径关系一致。

不要为了 8 镜创建 8 个不同葡萄园。

Scene reference 要帮助保持环境一致性，但不得把所有 Shot 锁成同一构图。

上一轮用户已经明确：

“葡萄较矮”

不是当前需要修复的核心问题。

因此不要为了把葡萄抬得极高而制造新的场景约束。

# 11. Director 目标：严格控制在约 8 镜

本 Pilot 推荐固定为 8 个叙事功能明确的 Shot。

## Shot 1 — Establishing

葡萄园建立镜。

展示地点、藤蔓、葡萄。

狐狸可以尚未进入主要构图。

重点：

environment establishment。

---

## Shot 2 — Fox Enters

狐狸沿葡萄园路径进入。

Medium-wide / full body。

自然四足 walking。

这是 calibration Shot B 能力的正式生产版本。

---

## Shot 3 — Discovery CU

狐狸发现葡萄。

Close-up。

抬头 / 耳朵轻动 / 眼神聚焦。

这是 calibration Shot A 能力的正式生产版本。

---

## Shot 4 — Observation / Preparation

狐狸观察葡萄。

调整位置。

轻微压低身体，准备跳跃。

不要在一镜塞太多动作。

---

## Shot 5 — The Jump

全片动作强度最高镜头。

狐狸：

短暂蓄力
→ 单次向上跳跃
→ 没有够到葡萄
→ 落地

一次 jump 即可。

不要连续三跳。

不要抓取葡萄。

不要让 Shot 依赖精确嘴部咬取。

Video prompt 使用 P1/base 思路。

不要默认加入：

“The grapes remain hanging on the vine throughout the shot.”

如果 candidate 出现葡萄掉落：

先视为 candidate quality 问题。

通过 variant selection 解决。

如果连续多个 variant 都失败：

再判断 shot staging / provider limitation。

不要重新走 P3 constraint escalation。

---

## Shot 6 — Reaction

狐狸落地后恢复平衡。

喘息 / 短暂停顿 / 失望或不甘。

以表演和情绪为主。

不要再加入第二次复杂跳跃。

---

## Shot 7 — Leave

狐狸转身。

沿路径离开葡萄园核心区域。

全身或 medium-wide。

强调：

identity + locomotion + emotional exit。

---

## Shot 8 — Final Image

葡萄仍在藤蔓上。

狐狸逐渐离开或已经远去。

画面负责收尾寓意。

旁白如果后续添加：

放在 post / Sequence narration layer。

不要为了旁白让视频里的狐狸开口说话。

---

# 14. Candidate Strategy

本 Pilot 的 production strategy：

> 少量候选，而不是单次赌博，也不是无限 reroll。

每镜：

首先生成：

`2 candidates`

两条必须尽量保持：

* 同 production truth；
* 同 R3 reference；
* 同 style；
* 同 P1/base prompt density；
* 同 Shot intent。

目的：

观察正常 stochastic variation。

如果其中已经有生产可用 candidate：

停止该 Shot 继续生成。

只有当：

两个都明显不可用

才允许生成：

`candidate 3`

第三条仍优先：

same recipe regeneration。

不要马上重写成一个更长、更严格的 prompt。

因此 8 镜预计：

约 16 个基础 candidate。

实际总量通常应控制在：

16–20 左右。

不要默认直接生成：

8 × 5 = 40 条。

# 15. Candidate 评价维度

每个 candidate 至少记录以下事实。

### Character

* fox identity；
* face；
* fur/color；
* left-ear anchor（如使用）；
* body proportion；
* tail；
* species stability。

### Motion

* locomotion；
* four-legged anatomy；
* jump；
* landing；
* balance；
* motion fluidity；
* temporal stability。

### Camera

* framing；
* shot size；
* camera motion；
* subject scale；
* cinematic readability。

### Scene

* vineyard consistency；
* lighting；
* grape appearance；
* unexpected background objects；
* reference leakage。

### Object

重点关注葡萄：

* disappearing；
* morphing；
* unexpected multiplication；
* unexpected falling；
* geometry instability。

但必须结合 Shot narrative 判断。

Calibration 中的判定不能机械复制到正式故事。

正式故事中：

如果某 Shot 的葡萄变化破坏剧情，

就应判为 production problem。

### Hard Failures

* duplicate fox；
* extra fox；
* extra limbs；
* severe anatomy collapse；
* species transformation；
* character disappearance；
* major background leakage；
* object deletion；
* broken temporal continuity。

### Audio

对正式 candidate 必须听：

* 是否有 BGM；
* 是否存在合理 native SFX；
* walking 是否有合理 footsteps；
* jump / landing 是否有合理动作声；
* 是否出现与画面无关的声音。

目标：

`No BGM + believable on-location/native sound`

# 20. Regen 决策顺序

全 ❌ 后严格按下面思路处理。

### A. System Error

例如：

* wrong reference；
* missing binding；
* stale basis；
* wrong model；
* prompt compiler bug；
* wrong scene；
* provenance mismatch。

修真正系统问题。

然后重新生成。

---

### B. Agent / Production Planning Error

例如：

Director：

* 一镜动作太多；
* framing 与动作不匹配；
* cast 错；
* 选择错 reference；
* scene state 错。

让对应 Specialist 正式修改。

不要手工 patch canonical。

---

### C. Provider stochastic failure

production truth 正确，

prompt 也合理，

只是一条随机失败：

直接：

`same-recipe regeneration`

---

### D. Repeated model limitation

如果相同失败连续多 candidate 出现：

不要继续加 prompt。

优先考虑：

* 更简单的 staging；
* 更安全的 camera；
* 把复杂动作拆镜；
* 避免极高 precision interaction。

但保持故事意义。

记录：

`MODEL_LIMITATION`

# 21. 关于 Shot 5 葡萄问题的专门规则

这是本 Pilot 最重要的已知风险之一。

狐狸跳跃镜如果：

Candidate A：
葡萄掉落

Candidate B：
葡萄稳定

直接选择 B。

不要修改系统。

如果：

A / B 均出现葡萄问题

允许：

Candidate C same-recipe regeneration。

如果：

A / B / C 都出现严重葡萄变化：

停止 prompt escalation。

让 Director重新思考 staging。

例如可以：

* 调整狐狸与葡萄的屏幕空间关系；
* 使用更清晰的 miss trajectory；
* 调整机位；
* 避免视觉上发生接触；
* 必要时把 landing reaction 留给下一镜。

不要继续堆：

“The grapes NEVER move...”

之类约束。

# 23. Continuity Review

8 个 winner 确定以后：

做一次真正的跨镜连续性审查。

重点看：

### Fox

* 是否仍是同一只；
* face；
* fur；
* ear anchor；
* body proportion；
* tail；
* species；
* animation style。

### Vineyard

* light；
* time；
* vines；
* path；
* grapes；
* environment style。

### Narrative

动作是否形成：

enter
→ notice
→ prepare
→ jump
→ recover
→ leave

而不是各镜单独好看但串起来不成立。

### Transition

检查：

Shot N end state
→ Shot N+1 start state

是否合理。

特别注意：

* fox location；
* facing direction；
* pose；
* movement direction；
* grape relationship。

# 24. Sequence / Assembly

Human Selection 和 continuity PASS 后：

调查当前是否已经有正式：

* Sequence；
* Assembly；
* selected VideoVersion consumer；
* trim；
* render/export。

如果已有：

使用已有正式能力把 8 条 selected video 按顺序组成 Pilot Sequence。

不要新造第二套 timeline。

如果已有 Assembly / Compositor Agent：

通过正式 Agent。

如果目前只有稳定的 deterministic Sequence backend：

允许使用正式 backend/API 进行简单 assembly。

但：

**本阶段不要为了这个 Pilot 新开发一个大型 Assembly Agent。**

如果当前 Assembly capability 缺失：

把 8 个 selected production videos + ordering + duration + audio facts 完整交付。

Assembly 不作为动物视频 Pilot 的硬阻塞。

# 25. Narration / BGM

架构原则：

Shot video 自带：

`native / diegetic SFX`

Shot video 不应自带：

`BGM`

Narration 与 BGM：

`post production`

如果当前正式 Sequence Audio Layer 已经能够消费：

* narration artifact；
* music artifact；

可以在最终 assembly 加入。

如果当前还缺通用 narration generation：

不要为了 Pilot 把旁白伪装成 `Shot.dialogue`。

不要因此重构 Audio Backend。

保留：

* narration text；
* cue；
* intended timing；

作为后期资产需求即可。

同理：

如果没有正式 AI Music generation：

不要在本阶段新造 Music Generator。

---

# 26. 什么算 Pilot PASS

Pilot PASS 不代表：

8 个 Shot 第一条全部完美。

真正 PASS 应表示：

1. 一个完整寓言项目由正式 canonical 建立；
2. Producer / Specialists 能围绕同一项目协作；
3. Fox production reference 使用 R3 已验证策略；
4. 8 个 Shot 都有正式 production binding；
5. 8 镜均至少获得一个用户认为可保留的 candidate；
6. selected videos 中不存在系统性动物身份崩坏；
7. walking / CU / jump / reaction / leave 能共同构成一条完整叙事；
8. vineyard / fox / style 的跨镜连续性达到可接受水平；
9. 已知模型失败主要能通过有限 variant selection 管理，而不是无限 prompt engineering；
10. selected videos 满足或基本满足：
    `no BGM + native SFX present`；
11. 所有 provenance / generation basis / selected version 可追踪；
12. 能形成一个按顺序播放的完整 Pilot，或已经具备确定性的 Assembly handoff。

---

# 27. 什么情况才算真正 BLOCKER

只有以下类型才应阻止 Pilot 收口：

### System blocker

正式 pipeline 无法：

* 创建 reference；
* 建立 binding；
* 正确消费 R3；
* 记录 provenance；
* 保存/选择 VideoVersion；
* 维持 canonical truth。

### Systematic animal failure

即使：

正确 R3
+
正确 P1/base
+
合理 shot design
+
有限 regeneration

仍然无法在 CU / walk / jump 中维持狐狸身份或基本解剖。

### Systematic audio violation

正式请求正确，

但所有生产 candidate 都持续：

* 自动生成明显 BGM；
* 完全没有必要现场音；

达到无法通过 selection 管理的程度。

单条随机坏视频：

不是 BLOCKER。
