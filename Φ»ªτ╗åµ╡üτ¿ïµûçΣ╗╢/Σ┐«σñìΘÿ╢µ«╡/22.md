---

# 1. 本阶段总目标

目标不是：

> 找到 Agnes 的最高画质上限。

也不是：

> 用大量测试证明能生成电影级镜头。

目标是：

> **确认并建立一套足够灵活、确定、可被未来 Director Agent 使用的 Shot Performance Control。**

系统必须能够明确表达：

```text
角色是谁
角色在哪里
角色先做什么
再做什么
最后做什么

角色此时是什么情绪
情绪强度如何

重要道具是什么
由谁持有
大致保持什么状态 / 朝向
哪些连续性不能在镜头中随机改变

镜头如何运动
画面如何变化

谁说话
说什么
```

然后把这些事实稳定编译给 Agnes。

# 6. 第一重点：Action Sequence Control

C1 人评已经出现：

> 分镜要求人物绕楼梯行动，但实际没有按照要求执行。

因此首先审计：

```text
action_sequence
opening_state
end_state
motion
BindingAction.start_state
BindingAction.end_state
BindingAction.note
```

是否真正进入最终 Agnes prompt。

如果已经进入：

检查它们是否只是被平铺成一段模糊 description。

---

# 7. 动作必须表达“顺序”

不要仅仅给：

```text
角色走到楼梯附近，移动，观察环境，然后继续前进。
```

如果 canonical 是明确顺序：

```text
A
→ B
→ C
```

compiler 必须保留：

```text
first
then
after that
finally
```

这种明确 temporal ordering。

例如语义：

```text
First, the character approaches the staircase.
Then the character walks around the staircase rather than through it.
After clearing the staircase, the character turns toward the doorway.
```

具体措辞根据 Agnes 当前验证经验决定。

关键不是英语模板。

关键是：

> canonical 中存在的动作顺序不得在 prompt compiler 中丢失。

---

Creative decisions 继续属于上游 Director。

# 9. 第二重点：镜内物体连续性

C1 人评真实问题：

> 手枪拿起以后方向发生变化。

这属于：

```text
within-shot object continuity
```

不是跨 Shot Resource consistency。

先审计当前：

```text
prop bindings
resource references
BindingAction
opening/end state
production notes
visual prompt
```

是否已经拥有：

```text
谁持有什么
在哪只手
初始状态
最终状态
动作过程中应该保持什么
```

的信息。

如果已有：

compiler 强化。

如果确实没有表达能力：

允许增加一个**最小 production-level continuity seam**。

---

# 10. 如果需要新增字段，只允许最小 continuity constraint

优先挂在：

```text
ShotProductionBinding
```

不要改 Script / Story canonical。

例如概念上：

```text
continuity_constraints:
    - subject: "顾岩的手枪"
      requirement: "保持在右手，枪口方向在抬起过程中不要随机翻转"
```

但：

> 只有代码审计证明现有 BindingAction / prop state 无法表达时才能增加。

不要先按此示例直接实现。

报告必须提供：

```text
为什么现有字段不够
```

的代码证据。

---

# 11. Continuity Constraint 必须是 production intent

不要把它做成物理模拟系统。

不需要：

```text

XYZ rotation
frame-by-frame tracking

pose tracking
```

当前目标只是告诉生成模型：

> 这是一个重要连续性约束。

如果模型偶尔仍随机违反：

允许通过：

```text
variant regeneration + selection
```

解决。

不要为了随机生成边界建设视觉追踪系统。

# 13. 如果确实不存在最小表演意图

# 14. 表情必须和动作 / 对白共同编译



目标是让模型理解：

> 动作、面部表演和对白属于同一场表演。

这才符合 Native AV 模型。

# 20. 不要求百分之百 deterministic visual compliance

生成模型有随机性。

成功标准不是：

```text
3/3 每一个像素都完全符合
```

而是：

> 系统提供的控制确实能提高成功概率，并且 Agent 将来可以通过 regenerate / selection 利用这种控制。

如果：

```text
baseline 成功率低
C2 明显更容易得到正确 variant
```

就是正收益。

# 21. Capability Boundary

如果经过少量有针对性的 prompt / compiler 尝试后：

```text
某种动作
某种物体连续性
某种表情
```

仍然经常失败：

不要无限调 prompt。

记录：

```text
provider capability boundary
```

并判断未来由：

```text
better model
regeneration
variant selection
alternative provider
```

解决。

不要为了绕一个模型限制污染整个 canonical。

```text

```

如果没有新增 canonical：

不要为了测试方便创造 schema。

# 29. 阶段成功定义

不要用：

> “所有镜头都完美。”

作为成功标准。

C2 成功意味着：

> **系统可以明确表达并有效控制关键动作顺序、重要镜内连续性以及角色表演/情绪，而且这些能力足够灵活，可以被未来 Director Agent + Skills 进一步利用。**

如果这个条件成立：

```text
SHOT PRODUCTION BACKEND V1
可以阶段性冻结
```

之后系统质量上限的继续探索：

```text
交给 Agent + Skills
```

而不是继续无限扩 backend。
