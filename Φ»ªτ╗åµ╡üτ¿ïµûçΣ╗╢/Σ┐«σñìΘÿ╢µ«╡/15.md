# 1. 本阶段真正目标

不是“给项目加一个 TTS 按钮”。

目标是建立以下生产真相：

```text
Dialogue
   │
   │  what is said
   ▼
canonical dialogue truth

Character
   │
   │ owns voice identity
   ▼
CharacterVoiceProfile
   │
   │ who this person sounds like
   ▼
VoiceGenerationPack
   │
   │ deterministic generation projection
   ▼
MiniMaxVoiceAdapter
   │
   ▼
speech-2.8-turbo
   │
   ▼
DialogueAudioVersion
   │
   │ generated artifact + provenance
   ▼
selected / approved audio
```

必须做到：

> 台词变化时，旧声音 stale。

> Voice Profile 变化时，旧声音 stale。

> 无关角色 Voice 变化时，本句声音不能 false-stale。

> read 不得自动 regenerate。

> refresh / regenerate 必须 explicit。

# 3. 第一件事：真实代码审计

任何修改之前先审计当前仓库。

重点回答：

## A. Dialogue 当前真相在哪里？

检查：

```text
Script Writer
Project model
Shot
Scene
script storage
existing dialogue-related model/service
```

必须确认：

1. 是否已有 stable Dialogue ID；
2. speaker 如何表示；
3. dialogue text 当前 canonical 在哪里；
4. language 是否存在；
5. delivery / performance intent 是否存在；
6. revision / fingerprint 有没有；
7. 是否有重复 dialogue text 被多个模块复制。

### 强规则

如果已有 authoritative Dialogue entity：

```text
MUST reuse it
```

不得另建 Voice 自己的：

```text
tts_text
speech_text
audio_text
```

作为第二套真相。

Voice generation 必须通过：

```text
dialogue_id
```

解析 canonical text。

---

## B. 如果当前没有稳定 Dialogue ID

不要偷偷使用：

```text
shot_id + index
```

也不要使用：

```text
hash(text)
```

冒充业务 identity。

首先判断能否非常局部地补一个：

```text
DialogueLine
```

最小语义：

```text
dialogue_id
speaker_character_id
text
language
delivery_intent
revision / fingerprint
```

Ownership：

```text
Script Writer
```

如果这个最小 canonical 可以在不重构 Script Writer / Shot / Scene 的情况下加入：

允许实施。

如果正确引入 Dialogue identity 需要：

```text
大规模 Script Writer migration
Shot schema redesign
Scene schema redesign
Agent refactor
```

则 STOP。

报告：

```text
VOICE_A1_BLOCKER:
stable dialogue identity is missing and cannot be added locally
```

不要为了继续 TTS 而复制 dialogue truth。


```text

```


```text

```

# 21. DialogueAudioFreshness

实现 derived：

```text
MISSING
CURRENT
STALE
```

### MISSING

没有 selected approved audio。

### CURRENT

selected audio 的 generation_basis 与当前：

```text
Dialogue
+
VoiceProfile
```

一致。

### STALE

任一实际 dependency 变化：

```text
Dialogue text changed
speaker changed
VoiceProfile revision changed
provider voice changed
relevant synthesis defaults changed
```

```text

```


# 24. Race Protection

生成流程：

```text
read Dialogue
read VoiceProfile
compile Pack
resolve provider request
provider dispatch
```

之间可能发生修改。

因此至少：

### pre-build

确认 READY。

### pre-dispatch

重新确认：

```text
dialogue fingerprint
voice profile revision
```

仍与 Pack basis 一致。

若相关 dependency 在生成窗口变化：

```text
dependency_changed_before_voice_generation
```

provider 调用必须：

```text
0
```

不要生成一个基于混合状态的音频。

无关 Bob VoiceProfile 变化不得阻断 Alice。
