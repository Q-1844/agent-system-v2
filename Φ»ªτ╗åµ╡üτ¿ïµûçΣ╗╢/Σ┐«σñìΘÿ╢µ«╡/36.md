## §1 尾帧接力成片方法（已验证，2026-09-23/24 六层实验+雨林全链）

### 1.1 标准生产流程

```
预编剧（固定故事，每镜含「预期尾帧」描述 + 时长）
  → 首镜参考选型【identity+environment+style 三重锚定】
  → 逐镜生成（multi 模式：首镜=参考图，后续镜 video_reference_asset_id='prev_tail'）
  → 每镜完成自动：末帧提取 → JPEG q88 → GithubPagesHost 上传 → 轮询就绪（35.md 管线）
  → 下一镜 relay 解析上镜末帧 → 强条件化开场
  → 【校准检查点】每镜尾帧 vs 预期尾帧 → 按 §2 协议调整
```

### 1.2 关键技术组件（全部已实施验证）

1. **链根参考=三重锚定**：新环境故事的首镜参考必须 identity+environment+style 三者匹配。
   做法：`derive_look_reference` 从姿态图 i2i 派生，prompt 带强 2D 风格指令+环境描述
   （实证：ref_d27e1a01c36f 雨林 walk_side 变体，identity/costume/defects/style 四维全过审）。
   ✅ 解法了 v1e 的组间形象跳变（R3 系静帧 vs 尾帧链的风格/形象断层）。
2. **prev_tail 哨兵 + 末帧托管**：`video_reference_asset_id='prev_tail'` → adapter 解析上镜
   `video_end_frame.url`；末帧由 Phase 6A 自动提取 → JPEG q88 → Pages（imgbb 已退役）。
3. **prompt 链路（🔴 今日发现的缺口，必须遵守）**：
   `update_shot_fields` 改字段后 **prompt_en 不自动重建** → 必须
   `POST /shot/{id}/prompt/generate {stage:'video'}` → `PUT /shot/{id} {prompt_en: <文本>}`。
   漏掉此步 = 视频用旧剧本（v1e/v1f 的自适应描述曾因此全部未生效）。
4. **分组与时长**：动作镜给足时长（8-10s）让动作弧完整展开+收势——**尾帧落在稳定态**，
   下一镜接力质量高；5s 动态镜的尾帧易停在动作高点（不稳定）。组内接力、组间按 §2 校准。
5. **场景系统**：新环境需正式 Location（`POST /scene-system/locations`，描述**显式禁 fauna**
   ——空场景板审查严格，rainforest 会吸引动物入画）→ LocationView（生成+审查+批准）→
   每故事段 SceneInstance（PATCH location + state）→ SIV（生成+审查+批准）→ binding 刷新
   （OCC：`GET /shot-bindings/{id}` 取 binding_revision）。

## §2 自适应校准协议（用户方案，正式化）

**原则：故事是预先写好的；尾帧用来校准下一步动作；必要时加情节。**

每镜完成后比对【实际尾帧】vs【预编剧的预期尾帧】：

| 偏差等级 | 处置 | 实拍案例 |
|---|---|---|
| 无偏离 | 按预编剧继续 | v1f s02→s03 |
| **小偏离**（状态/位置略偏） | 下一镜描述**加过渡动作**，顺势衔接 | v1g s02 预期奔跑→实得正面特写 → s03 加「转身起跑」 |
| **大偏离**（叙事走偏） | **插入小情节把故事拉回正轨** | （待实拍；协议已定） |

**系统化方向（阶段 C）**：把协议做成 agent 工作流——vision 看尾帧 → 偏差分级 →
自动/半自动修改下镜字段 → prompt 重建（§1.2.3）→ 接力生成。闭环后"做任何视频都没问题"。

## §3 Agnes 限制与对策（完整清单）

| # | 限制 | 对策 |
|---|---|---|
| 1 | 视频接口只吃公网 URL 图片（无 base64，FACTS §3.3） | ImageHost 抽象层；GithubPagesHost 已默认（35.md） |
| 2 | 参考强条件化开场（~0.7-2.8s 复刻前缀） | 参考选型=开场设计；prompt 压不过参考 |
| 3 | **seed ∈ [-1, 999]**，越界=provider 400（伪装成 provider_failed） | 所有生成调用 seed 必须在此范围 |
| 4 | 速率限制（Token Plan 只解决日桶量：视频 500s/天、图 4000/天）：图片连发→`provider_failed`/生图队列满 503；视频串行 1 RPM | 节奏化调用（图片间隔 ≥80s）；视频走 JobQueue 串行 |
| 5 | prompt 注入故事段语义（段上下文+模型先验） | **完全不同的故事必须新建故事段**（描述级修改到顶） |
| 6 | 参考链继承道具/场景元素（葡萄/栅栏穿越 prompt 排除） | 链根参考必须环境匹配（§1.2.1）；或新故事段 |
| 7 | 双足/正面特写吸引子（文本姿态约束不可靠） | 姿态靠参考图规避；出现时按 §2 校准 |
| 8 | imgbb 已退役（i.ibb.co SNI 级阻断+key 拒收） | GithubPagesHost；回退=config 一行 |
| 9 | GitHub 路由注意：raw.githubusercontent.com 2/10 可达（弃用，用 `<user>.github.io`）；SteamTools 加速器 MITM 本地根（python 验证失败→`_system_verify()` 已兼容；**遇 github TLS 问题先关加速器**） | 已内置 |
| 10 | worker 错误格式化丢消息（httpcore.ReadError→空错误） | 待修（§4.2）；排障看 backend_runtime.log traceback |

**备选视频 provider（用户资源）**：用户手里有**日常免费生视频 API**（速度较慢）——
可类比 image_provider 的覆盖模式（scene 系统已有 `image_provider: sensenova` 先例）做
video provider 切换，用于配额溢出/限流分流/成本对冲。集成属阶段 B/C 工作量。
