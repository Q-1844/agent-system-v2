# Sequence S1 — Assembly Foundation

当前上游状态：

```text
SHOT PRODUCTION BACKEND V1
FREEZE
```

依据：

C1 已完成 Native AV productionization。

C2 已证明 Action Sequence Control 具有明显正收益。

C2.1 已完成刚性道具 interaction 边界定界：

```text
Agnes prop-interaction provider capability boundary
```

当前 Shot canonical 已能够表达必要生产事实。

除非发现新的明确 system-level missing capability：

> 不再扩展 Shot Production backend。

---

# 1. 本阶段目标

建立一个独立：

```text
Sequence Assembly
```

后端模块。

它负责：

> **把多个已经完成的有声 Shot / VideoVersion 按顺序组合成一个可播放、可导出的连续 AV 片段。**

这是从：

```text
High-quality Shot Production
```

进入：

```text
High-quality Sequence Production
```

的第一步。

本阶段暂时不追求：

```text
完整电影自动剪辑
```

只建立可靠的 Sequence Block。

---

# 2. 为什么独立模块

当前不要把 Sequence 直接塞进 Shot / Storyboard 模块。

保持：

```text
Shot Production
→ 生产一个镜头

Sequence Assembly
→ 组织几个镜头
```

独立模块有利于：

```text
快速修改数据结构
快速调整 API
快速验证 timeline 语义
未来 UI 独立实验
```

等系统成熟以后，如果产品体验证明：

> Sequence 操作天然应该融入 Storyboard 页面

再由前端合并。

后端 domain boundary 可以继续保持。

---

# 3. Shot Production 全部冻结

Sequence 不得修改：

```text
Shot canonical
VideoVersion generation
NativeAVGenerationPack
Native AV Prompt Compiler
Visual V1
C1 freshness/race
C2 performance control
A1
A2
Agnes adapter
```

Sequence 是：

> Shot Production 的消费者。

不是它的第二个入口。

# 4. 开工前先审计现有仓库

先完整搜索是否已经存在：

```text
timeline
sequence
editor
concat
assembly
render
export

```

重点确认：

现有 Story / Scene 是否已经拥有 Shot ordering truth。

现有项目是否已经存在 timeline-like 数据。

是否已有 ffmpeg helper。

是否已有 JobQueue 可以复用。

如果已经存在相关能力：

> 复用和扩展。

禁止因为规格里叫 Sequence 就直接创建第二套 timeline truth。

最终报告必须给出代码证据。

---

# 5. Sequence canonical 的职责

如果审计确认没有现成对象可以承担：

新增最小：

```text
SequenceBlock
```

它只表达：

```text
哪些 Shot
什么顺序
使用哪些裁切区间
```

不要让它表达：

```text
镜头里面发生什么
人物是谁
台词是什么
画面 prompt
声音 prompt
```

这些都已经属于 Shot。

---

# 6. 推荐最小结构

具体类型名允许按仓库风格调整。

语义类似：

```text
SequenceBlock:
    sequence_id
    title?
    scene_id?
    revision

    clips:
        - shot_id
          trim_in_ms
          trim_out_ms
```

最重要原则：

> Sequence canonical 默认引用 Shot，而不是复制 VideoVersion 文件路径。

不要复制：

```text
dialogue
character
video path
audio path
prompt
```

---

# 7. Source Video Truth

每次准备 render Sequence 时：

```text
clip.shot_id
    ↓
Shot.final_video
    ↓
VideoVersion
    ↓
authoritative source mp4
```

必须复用已经建立好的 final video truth。

禁止：

```text
glob 最新 mp4
mtime 猜最新版
默认 video_versions[-1]
扫描 output 目录
```

---

# 8. Canonical 与 Render Dependency 分离

SequenceBlock 表达：

```text
我要哪些 Shot，以及顺序和 trim
```

具体一次 render 使用：

```text
shot_id
→ 当前 final_video version_id
```

在 dispatch 时解析。

因此：

> Shot 的 final_video 后来换了，不需要修改 SequenceBlock canonical。

但旧 Sequence Render 应变为：

```text
STALE
```

---

# 9. SequenceRenderVersion

建立生成结果对象：

```text
SequenceRenderVersion
```

它是 artifact version，不是新的故事 canonical。

至少记录：

```text
version_id
sequence_id

output_file

duration_ms

generation_basis

source_video_versions

created_at

status
```

如仓库已有 artifact version 范式：

严格复用。

---

# 10. Render selection

推荐采用现有 VideoVersion 一致哲学：

```text
render_versions[]
+
selected/final render pointer
```

不要：

```text
最后生成的自动覆盖正式结果
```

生成：

```text
append version
```

选择：

```text
explicit select
```

如果当前项目对于这种 derived preview 不需要 approval：

不要无理由复制完整 Shot approval workflow。

先审计现有版本体系后做最小实现。

---

# 11. S1 只支持 Hard Cut

第一版只实现：

```text
Shot A
CUT
Shot B
CUT
Shot C
```

不要实现：

```text
crossfade
dissolve
wipe
speed ramp
J-cut
L-cut
```

原因：

> 先建立可靠 timeline truth。

电影剪辑效果以后再加。

Hard Cut 本身已经足够验证 Sequence foundation。

---

# 12. Trim

每个 clip 支持：

```text
trim_in_ms
trim_out_ms
```

定义必须明确。

推荐：

```text
trim_in_ms
= 从源视频开头裁掉多少

trim_out_ms
= 从源视频结尾裁掉多少
```

或者仓库已有 media convention 则沿用。

必须验证：

```text
0 <= trim_in
0 <= trim_out

trim_in + trim_out
<
source_duration
```

非法：

```text
FAIL CLOSED
```

不要自动修正用户数字。

---

# 13. Timeline Plan

render 前建立纯派生：

```text
SequenceTimelinePlan
```

性质：

```text
ephemeral
deterministic
zero provider call
```

例如：

```text
clip 0
source duration 6000
trim 0 / 500
effective 5500
timeline 0 → 5500

clip 1
source duration 8000
trim 500 / 500
effective 7000
timeline 5500 → 12500
```

Sequence 总 duration：

```text
sum(effective clip durations)
```

S1 没有 transition overlap，因此计算必须精确。

---

# 14. Media probe

所有 source duration/spec：

```text
ffprobe
```

读取。

禁止：

```text
根据 Shot.target_duration_s 猜
根据 provider request duration 猜
根据数据库历史值猜
```

最终媒体事实必须从文件读取。

# 15. Native Audio 是 Source 的组成部分

当前每个 VideoVersion：

```text

```

Sequence S1 必须把它作为一个整体 clip。

禁止：

```text
提取对白
替换声音
重新 lip-sync
source separation
重新生成 Audio
```

S1 只：

```text
trim AV together
+
concatenate AV together
```

# 16. Production Media Spec

由于未来不同 provider / model 可能产生不同：

```text
resolution
frame rate
audio sample rate
audio codec
```

Sequence render 必须建立一个确定性的 production output profile。

开工前审计当前项目真实视频规格。

然后选择最小统一输出，例如语义上：

```text
video:
H.264
fixed project resolution
yuv420p

audio:
AAC
48 kHz
stereo
```

具体 bitrate / CRF / fps：

优先复用项目现有 export/media policy。

如果没有：

建立一个简单稳定的 SequenceRenderProfile。

不要为了 S1 做完整 codec configuration system。

---

# 17. 不做 Loudness Normalization

特别注意。

S1 不执行：

```text
LUFS normalization
compressor
limiter
per-shot gain matching
dialogue ducking
```

原因：

这些属于后面的：

```text
Sequence Audio / Final Calibration
```

S1 只保证：

> 原 native audio 正常保留、AV sync 正确。

不同 Shot 音量暂时有差异是允许的。

这反而可以为后续 S2 提供真实需求。

# 20. Sequence Freshness

建立纯 derived：

```text
SequenceRenderFreshness
```

状态：

```text
CURRENT
STALE
UNTRACKED_LEGACY
MISSING
```

STALE 至少包括：

```text
Sequence ordering changed
trim changed

某个 Shot.final_video changed
source file fingerprint changed

render profile changed
renderer schema changed
```

无关 Shot 变化：

```text
CURRENT
```

# 21. Final Video 更新的语义

例如：

```text

```

```text

```

```text
不变
```

旧 SequenceRenderVersion：

```text
STALE
```

> sequence should be explicitly re-rendered

但：

```text

```

---

# 22. No Auto Render

和 Video Production 一样：

```text
detect
→ expose
→ explicit render
```

SequenceBlock 修改：

不得自动执行 ffmpeg。

Shot final_video 修改：

不得偷偷重建 Sequence。

---

# 23. Race Guard

Sequence render 也可能耗时。

采用三阶段：

```text
Phase 1
snapshot sequence + source video versions + basis

Phase 2
ffmpeg render
no project lock

Phase 3
recompute
```

如果期间：

```text
shot final_video changed
sequence order changed
trim changed
```

则：

```text
sequence_dependency_changed_before_commit
```

不得 attach 为 CURRENT render。

可保留输出为 evidence。

机器验证：

```text

≈
```

# 36. 工程原则

Shot Production 已经回答：

> 一个镜头怎样生成得好。

Sequence Assembly 现在只回答：

> **几个已经好的镜头，怎样可靠地成为一个完整片段。**

不要在 Sequence 阶段重新导演 Shot。

不要修改 Shot 内部媒体。

不要修 Agnes 的枪。

不要重新生产声音。

只组织已经批准的 AV Shot。
