## §2 已验证方法（必须遵守，勿重新发明）

### 2.1 标准逐镜链路

```
预编剧冻结（每镜 description/motion/expected_tail/duration 齐备）
→ 字段落库 update_shot_fields（正式路径，自动 invalidate 旧 prompt）
→ prompt 重建（生成前自动；或 POST /shot/{id}/prompt/rebuild 显式做）
→ binding refresh（OCC：GET binding_revision → POST refresh）
→ multi 生成（首镜=链根参考直生 video_reference_asset_id=链根ID；其后=prev_tail 接力）
→ 等末帧就绪（自动提取 + JPEG q88 + Pages 托管）
→ MAE（128 灰度，历史同刻度）+ Vision 11 维评估（tail_assessment，仅证据）
→ 人工裁定（none/minor/major + reason）→ trace 落档 → 下一镜
```

### 2.2 校准与修复方法论（第一轮实证）

- **三档协议**（37.md §5/36.md §2）：none=按预编剧继续；minor=下一镜**预编剧首句**吸收
  （第一轮 5/5 成功，零文字修改）；major=先判断再动手。
- **major 判据（第一轮归纳，继续验证）**：
  - 叙事/情绪与剧本相反 → **retry**（单次重试可同时修复机位+情绪+地理，2/2 实证）；
  - 叙事命中但机位偏（特写吸引子）→ 可 accept+adapt（特写→大远景是标准电影语法）；
  - 叙事命中但动作端点未落尾帧 → accept+adapt（下一镜吸收）；
  - 接续不可修复 → **keyframes 桥**（§2.3）。
- **特写吸引子对策**：日光/环境锚定文本 + 日光接力参考组合可压制（N4 r2 实证）；
  「静止收势」类尾态文本压不住 → 直接用 keyframes 钉死。
- **时长配方**：静态/反应镜 5s；动态镜 8s；高运动/复杂交互 10s（9/9 无截断）。
- **加情节的正式路径**：update_shot_fields 改 description/motion/action_sequence
  （receipt 在档）——第一轮 N6「好奇挪近」微情节实证；**最小改动、要给后续镜铺垫动机**。

### 2.3 keyframes 接续桥（用户方法，第一轮收官实证 MAE 2.9）

两镜接续不可修复时（尾帧与下一镜首帧状态差异大），**不重生成、插桥梁镜**：

```
1. 提取下一镜实际首帧：ffmpeg -i <下一镜.mp4> -frames:v 1
2. 上传 Pages 图床（GithubPagesHost，.env GITHUB_TOKEN）
3. insert_shots_after 插入桥梁镜（时长 10s；插完后 binding 创建+refresh）
4. update_shot_relay(桥, 上一镜)  +  REST PUT {opening_source: inherit_previous,
   link_mode: keyframes, transition_description: <过渡动作文本>, video_prompt_en: ""}
5. seed 尾帧：compile_reference_pack(桥).pack.basis → last_frame_batches 增批
   （candidates=[N+1 首帧 URL], generation_basis=basis）+ selected_last_frame 指针
   + last_frame Asset(url, status=done)
6. 提交生成（keyframes：首槽=上一镜尾帧、尾槽=下一镜首帧，provider 插值）
7. 验收：桥尾帧 vs 下一镜首帧 MAE（2.9=成功；多参考版对照 43.6 被吸引子劫持）
```

⚠️ **basis 时序坑**：seed 用的 basis 里含 binding_revision——**seed 之后不得再 refresh**
（会被顶掉报 boundary_frame_stale）；先 refresh 完、再 compile+seed、再提交。
⚠️ 系统缺口（37B 待正式化）：「提取帧作尾边界」目前是 script 级手术，无正式端点。

## §3 系统坑清单（踩过的，必读）

1. **SIV fauna**：SIV 生成 prompt 只读 location 的 `identity_description`（不读 description）
   ——禁 fauna 条款必须写在 identity_description 里（"PURELY BOTANICAL empty plate…
   NO animals…"），否则雨林类场景板必混入动物（审查器 visual_defects 会 fail 且不给 notes）。
2. **location identity 变更 → 基础 View 指纹失效**：作为 SIV 母版会报 location_view_stale
   ——需对 View 重新 review + revoke + re-approve（刷指纹；复审用既有图不烧新图）。
3. **Vision 会误报 none**（N6-a1 把「开心脸+地理丢失」判完美）：Vision 只是证据，**人工必须看图**
   （Read 工具直接看末帧 jpg）。
4. **末帧提取失败**：同代码新进程成功=后端长进程环境退化，重启后端即愈（错误串已带
   rc/which/stderr-len 诊断）。
5. **seed ∈ [-1,999]**，越界=provider 400 伪装成 provider_failed。
6. **视频串行 1 RPM**（JobQueue 自动）；图片连发退避 ≥45-80s；SIV 清图循环用
   `_37_setup_scene_system.py` 的 clean_loop 模式（断点续跑幂等，approve 崩溃不重复烧图）。
7. **后台长任务用脱离式进程**（`subprocess.Popen(creationflags=0x00000200)` + 日志重定向，
   参考 `_launch_backend_detached.py`/`_37_review_server.py` 启动方式）——harness 会清理
   后台 bash 直系子进程；系统内存紧张时也会杀任务，杀掉的脚本按幂等断点续跑。
8. **旧 prompt 污染**（37A 已修但需保持纪律）：任何字段修改后 prompt 会自动 invalidate，
   生成前自动重建；**不要绕过 update_shot_fields/PUT 手改 project.json**。
9. **projects/ 不入 git**；每步验证后 commit（子仓库）+ 父仓库指针更新；每次回复结尾带
   「报告位置」（相对路径+commit）。
10. **人评节奏**（用户已授权模式）：Vision+执行者双读判 none → 按预编剧自动继续（页面补
    [已裁定]标记）；任何实质偏离 → 停下等用户裁定。用户在对话里给裁定（如「N1 minor 继续」）。
