Animal Character Creative Calibration V1

动物角色参考格式 + 视频提示词最小充分条件测试

你现在进行的不是新一轮大型系统开发，而是一轮非常小、非常受控的 Creative Calibration。

此前已经做过较大范围的视频生成能力测试。

本轮目的不是继续扩大镜头类型，也不是测试跨镜连续性，而是回答两个非常具体的问题：

什么样的动物角色参考图最适合当前视频生成模型保持角色身份，同时又不明显压制运动？

视频 Prompt 写到什么程度最合适？简洁动作意图、动作时序说明和额外约束，分别会怎样影响结果？

本轮测试结束以后，将使用结论制作第一部小型寓言 Pilot。

暂定 Pilot：

《狐狸和葡萄》

但本轮不要直接制作整部故事。

一、基本原则

这一轮禁止同时测试大量变量。

固定：

同一个 Provider；

同一个视频模型；

同一个项目视觉风格；

同一只狐狸；

同一基本场景；

同一画幅；

同一分辨率；

同一视频长度；

同一核心镜头意图。

本轮主要改变：

Character Reference Format；

是否使用 reference；

Prompt 信息密度。

不要同时修改：

风格；

Character design；

Provider；

视频时长；

大量生成参数；

镜头故事内容。

如果模型支持 seed：

记录并尽量做 paired comparison。

如果不支持：

如实记录，不得虚构 seed 控制。

二、不要先修改 Production Architecture

开始前调查当前真实代码和 Provider 行为。

确认：

当前视频模型；

当前真正支持的 reference 数量；

reference 输入形式；

是否支持 subject / image reference；

是否会把 reference 当成 first frame；

是否存在隐藏 fallback；

当前真实 prompt；

当前 provider payload；

当前生成产物与 provenance。

如果只是测试素材问题：

不要修改系统代码。

如果发现：

reference 没真正送进去；

模式映射错误；

prompt 被重复拼接；

reference 被错误当 first frame；

provenance 记录错误；

才允许做最小 deterministic 修复。

不得修改：

Resources ontology；

Scene System ontology；

Shot schema；

Binding canonical；

ReferencePack 核心语义；

Producer / Director 架构。

三、固定一个狐狸角色

建立或选择一只适合寓言动画的狐狸。

不要设计成复杂服装角色。

建议视觉身份保持简单但可辨识，例如：

red-orange fox fur；

white muzzle and chest；

darker lower legs；

large expressive ears；

amber eyes；

full bushy tail with a pale tip；

stable body proportions。

可以存在一个轻微但稳定的辨识特征，例如：

某一只耳朵轻微缺口；

特殊尾尖颜色；

稳定的眉眼形态。

不要同时增加：

帽子；

披风；

项链；

武器；

多层服装；

大量饰品。

这些会增加无关变量。

狐狸保持：

animal character

不要默认做人形化双足角色。

除非当前模型真实证明自然四足狐狸明显无法工作，再另行测试 anthropomorphic 版本。

四、固定一种视觉风格

本轮不要比较：

3D

水墨

赛璐璐

写实

儿童插画

多种不同 renderer

选择当前系统中已经证明视觉质量较好的一种风格。

建议方向：

cinematic storybook animation / stylized 2D cinematic animation

但最终应根据当前项目里真实表现较好的风格决定。

一旦选择：

本轮全部保持不变。

风格不是本轮变量。

五、制作三种 Character Reference

狐狸设计完全相同。

只改变 Reference Format。

R1 — Existing Character Plate

使用当前系统已有的标准角色参考格式。

例如：

white / plain background；

full-body；

当前 CharacterLook 或身份图。

不要人为美化结果。

它是当前 baseline。

R2 — Neutral Video Identity Reference

创建一张专门用于视频身份保持的单人物参考。

要求：

单只狐狸；

无文字；

无三视图拼版；

无多角色；

柔和中性背景；

角色占画面较大比例；

自然站立；

身体结构完整；

3/4 或轻侧角度；

光线均匀；

无强动作；

无复杂构图。

目的：

只负责告诉视频模型“这只狐狸是谁”。

不要让这张图承担故事构图。

R3 — Cinematic Identity Reference

仍然是同一只狐狸。

但参考图更接近真实动画镜头：

简化自然环境；

正常电影光线；

狐狸完整可见；

无复杂动作；

无其他主体；

无强构图要求；

环境不能抢主体。

目的：

测试：

更接近最终画面的 character reference 是否比角色板更容易被视频模型正确利用。

六、三个固定测试镜头

不要直接测试十几种 Shot。

只用下面三个。

Shot A — Close-Up Performance

目的：

测试：

face identity；

species consistency；

expression；

subtle motion；

CU compliance。

核心内容：

狐狸发现远处葡萄，略微抬头，耳朵轻轻动一下，目光变得专注。

摄影机：

Close-up。

动作必须很轻。

基础视频 Prompt

The fox notices something above and slowly raises its gaze. Its ears make a subtle natural movement and its expression becomes quietly attentive. The camera remains in a gentle cinematic close-up with very slight natural movement.

不要重新大段描述：

毛色；

耳朵颜色；

尾巴；

背景；

服装；

这些应由 reference / production facts 提供。

Shot B — Full-Body Walk

目的：

测试：

full-body anatomy；

quadruped locomotion；

identity during motion；

tracking camera；

body proportion stability。

核心内容：

狐狸沿葡萄园小路缓慢走过。

摄影机：

low-angle side tracking / medium-wide。

基础视频 Prompt

The fox walks naturally along the vineyard path at an unhurried pace. Its body and tail move with natural four-legged locomotion. The camera tracks smoothly alongside the fox at a low cinematic angle.

不要加几十条 gait constraint。

先观察模型自然运动能力。

Shot C — Simple Jump

目的：

测试：

dynamic animal motion；

anticipation；

leap；

landing；

identity during stronger motion。

核心动作：

狐狸看到高处葡萄。

蓄力。

向上跳一次。

没有够到。

落地。

不要：

咬葡萄；

抓葡萄；

葡萄掉下来；

葡萄被改变；

连续三次跳跃。

基础视频 Prompt

The fox crouches briefly, then makes one natural upward leap toward the hanging grapes. It does not reach them and lands back on the ground, regaining its balance. The camera follows the motion smoothly without an abrupt cut.

这是本轮动作强度最高的一条。

首先测试：

八、第一轮不要大量 reroll

每个组合先生成 1 条。

先看是否已经出现稳定差异。

只有以下情况才允许重复：

两种 reference 表现非常接近；

单次结果存在明显随机异常；

无法判断差异是否来自随机性。

这种情况下：

对相关组合再生成 1～2 次。

不要：

每个组合直接刷 5 条。

九、Reference Format 评价

每条视频至少评价：

Character

fox identity

face consistency

fur/color consistency

body proportion

tail consistency

species stability

Motion

locomotion

limb anatomy

motion fluidity

start motion

landing

temporal stability

Camera

framing

shot-size compliance

camera smoothness

subject scale

Reference leakage

特别检查：

白底进入视频；

reference plate 构图被复制；

角色像“贴”在画面里；

reference 导致动作僵硬；

reference 背景污染场景；

reference 姿态被过度锁定。

Hard failures

单独记录：

duplicate fox；

extra animal；

extra limbs；

human-like limb mutation；

face/species transformation；

tail multiplication；

severe body deformation；

character disappearance。

十、选出 Reference Format Winner

这里的 winner 不是：

“哪张静态图片最好看”。

而是：

哪一种 reference format 在多个镜头中最好地平衡：

identity consistency + natural motion + shot freedom。

至少要求在：

CU；

walking；

dynamic jump；

其中两个以上类型中表现稳定。

如果没有明显 winner：

保留“不足以下结论”。

不要人为决定。

十一、第二组：Prompt Density Test

Reference Format Test 完成以后：

只使用表现最好的 reference format。

选择：

Shot B 或 Shot C。

进行下面三个 Prompt level。

P1 — Minimal Creative Intent

例：

The fox walks naturally along the vineyard path. The camera tracks smoothly alongside it.

或者：

The fox makes one natural upward leap toward the grapes, misses them, and lands back on the ground. The camera follows the motion smoothly.

P2 — Minimal + Temporal Structure

例如 Jump：

The fox pauses beneath the grapes. It crouches briefly, pushes off the ground, makes one upward leap toward the grapes, misses them, then lands naturally and regains its balance. The camera follows the motion smoothly.

重点：

清楚动作顺序。

不增加大量视觉描述。

P3 — One Targeted Constraint

P3 不能提前编写一大串禁止事项。

必须先观察 P1/P2 的真实失败。

然后：

只针对一个重复出现的问题增加一条约束。

例如如果反复出现两只狐狸：

Keep a single fox in the scene throughout the shot.

如果反复出现葡萄掉落：

The grapes remain hanging on the vine throughout the shot.

如果没有这个错误：

不要加入这条约束。

十二、判断 Prompt 是否真的有帮助

比较：

P1 / P2 / P3

重点不是：

“谁最听话”。

而是同时比较：

motion quality；

identity；

camera；

temporal action；

artifacts；

overall usability。

如果：

P3 减少一个错误，

但同时明显导致：

movement stiffness；

camera degradation；

visual quality下降；

必须记录 trade-off。

不能简单把 P3 记为更好。

十三、停止无限 Prompt Engineering

如果同一种失败：

在正确 reference + 合理 P2 下，

重复多次仍然存在，

不要继续：

MUST STRICTLY NEVER EXACTLY ABSOLUTELY

无限追加。

改为判断：

reference issue；

model limitation；

shot design issue；

conditioning issue。

本轮目标是发现规律，

不是找到一条偶然成功的魔法 prompt。

十六、这一轮什么算 PASS

PASS 不代表：

狐狸每次都完美。

本轮达到以下状态即可进入 Pilot：

找到至少一种相对稳定的动物 Character reference 形式；

狐狸在 CU 与全身运动中能够保持基本身份；

简单 walking 具有可用运动质量；

单次 jump 至少能够产生生产可用 candidate；

没有无法解释的普遍 duplicate / anatomy collapse；

已经知道 Prompt 应保持到什么信息密度；

失败模式已经可以区分为 reference / prompt / model / system 问题。

如果动物角色本身在这些最基本镜头里都无法稳定工作：

不要开始完整寓言。

先停下来报告证据。

如果通过：

停止继续扩大 calibration。
