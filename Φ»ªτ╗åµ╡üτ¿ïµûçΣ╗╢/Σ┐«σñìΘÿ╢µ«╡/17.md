# Native AV B1 — Dialogue + Speaker Control

## 0. 阶段定位

执行依据：

* `NATIVE_AV_DIRECTION_REBASELINE_REPORT.md`
* `AGNES_AUDIO_DIRECTION_CORRECTION_REPORT.md`
* 已完成的 Agnes Audio Capability Probe / 人工评审证据

当前事实已经确认：

1. Agnes 当前生成的视频本身已经包含原生音轨；
2. Agnes 原生对白、口型、SFX、ambience 整体已经达到可用水平；
3. 当前生产链的主要问题不是“不会生成声音”，而是**系统没有把已有的声音意图正式交给 Agnes**；
4. 当前 `build_video_prompt` 不读取 `Shot.dialogue`；
5. 多角色 Shot 缺少正式的“哪句台词属于哪个角色”的表达；
6. 人工评审当前唯一明显的实质声音问题是：

   * 偶发 speaker swap；
   * 个别镜头声线偏差；
7. 本阶段只处理前者与台词控制，不处理声线参考。

本阶段目标：

> **在完全保留当前 Visual V1 视频生成方式的前提下，把准确台词和准确 speaker 信息正式接入现有 Agnes 视频生成链，并通过真实 Agnes E2E + 用户人工评审判断是否值得继续。**

这是一个**最小增量验证阶段**。

不是完整 Native AV 架构实施。

# 6. DialogueSpeakerBinding：只增加最小能力

本阶段允许在：

```text
ShotProductionBinding
```

增加一个**可选的小块**：

```text
dialogue_speaker_binding
```

推荐最小语义：

```text
lines:
  - index: 0
    speaker_character_name: "角色A"
  - index: 1
    speaker_character_name: "角色B"

resolution:
  "single_auto" | "explicit"
```

注意：

**不要复制 dialogue text。**

Binding 只表达：

```text
第 N 句 → 哪个角色
```

# 7. Dialogue line parsing

实现一个小型、确定性的 dialogue parser。

只做生产需要的最小能力。

## 7.1 单角色 Shot

如果：

```text
len(Shot.characters) == 1
```

允许：

```text
single_auto
```

所有可识别 dialogue line 自动归属该角色。

这与已有 A1 `resolve_speaker` 哲学保持一致。

---

## 7.2 多角色 Shot

如果：

```text
len(Shot.characters) > 1
```

优先读取显式：

```text
dialogue_speaker_binding
```

如果当前 `Shot.dialogue` 本身具有完全明确、可确定解析的：

```text
角色名：「台词」
```

格式，可以把它作为**解析辅助证据**。

但是：

> 不允许在真正存在歧义时猜 speaker。

如果无法唯一确定：

```text
FAIL CLOSED
```

返回清楚的 readiness / validation 信息。

不要：

* 默认第一个角色；
* 默认画面最大脸；
* 根据男女声猜；
* 让 LLM 临时猜；
* 静默继续生成。

---

# 8. Speaker 合法性

每个 resolved speaker 必须：

```text
speaker_character_name ∈ Shot.characters
```

非法 speaker：

```text
reject
```

并给结构化诊断。

不要自动往 `Shot.characters` 里添加角色。

不要静默纠错名字。

# 9. 新增一个极薄的 Dialogue Control Compiler

不要一开始建设完整 `NativeAVGenerationPack`。

B1 可以先实现一个很薄的 derived input，例如内部结构：

```text
NativeDialogueControl
```

或者同等内部对象。

语义类似：

```text

  - index

```

要求：

* derived；
* ephemeral；
* deterministic；
* 不持久化；
* 无 business ID；
* 不创造新的 truth。

如果现有代码更适合直接扩展 prompt builder，也可以不创建公开 dataclass。

**不要为了架构漂亮而增加对象。**

# 10. Prompt 编译规则

本阶段真正的核心就是这里。

现有 visual prompt 保持。

在其后增加一个**确定性的 Native Dialogue / Performance 段**。

目标不是写文学 prompt。

目标是明确告诉 provider：

1. 谁说话；
2. 说什么；
3. 用什么语言；
4. 谁不要说话。

示意语义：

```text
On-screen spoken dialogue:

Character A speaks in Mandarin Chinese:
「……」

Character B remains silent during this line.
```

多人多句：

```text
Dialogue sequence:

1. Character A says in Mandarin Chinese:
   「……」

2. Character B replies in Mandarin Chinese:
   「……」

Keep the dialogue assigned to the specified characters.
Do not swap the speakers.
```

这只是语义示例。

实施时可以根据此前 A0 已验证 prompt 经验调整措辞。

但是必须遵守：

### 台词文本

必须来自 `Shot.dialogue` 的原始切片。

不得：

* 改写；
* 总结；
* 润色；
* 翻译；
* 自动补词。

### Speaker

必须来自 resolved speaker binding。

### Language

本阶段只做最小语言强化。

如果项目当前已有明确语言信息，复用。

如果没有正式 language canonical：

本阶段不得为了 B1 创建大型语言系统。

可以把本轮 E2E 所需 language 作为：

```text
显式 caller / test input
```

或者使用当前项目已经明确存在的语言事实。

必须在报告中记录来源。

# 14. 自动测试范围

只写能保护本阶段改动的测试。

至少覆盖：

### Dialogue

* 无 dialogue → 现有 prompt 行为不变；
* 有 dialogue → 原文进入 dialogue block；
* 不改写台词；
* deterministic。

### Speaker

* 单角色 → single_auto；
* 多角色 + explicit binding → 正确；
* 多角色缺 binding / 无法唯一解析 → fail closed；
* speaker 不属于 `Shot.characters` → reject；
* 多句顺序保持。

### Legacy / regression

* feature flag OFF → 当前生成请求保持等价；
* Visual prompt 原有内容不丢；
* first/last/keyframe/reference behavior 不变；
* 不出现 `audios`；
* 不出现 reference mode；
* A1 / A2 零依赖。

不要为了测试数量扩范围。

## Sample D — 双角色但只有一人说话

# 17. 尽量做 A/B 对照

对于关键 Sample，尽量保存：

```text
A = 当前生产方式
B = B1 Dialogue + Speaker Control
```

保持尽可能相同的：

* Shot；
* visual references；
* model；
* duration；
* generation mode。

生成模型本身具有随机性，所以不要把单次 A/B 当统计学证明。

目的只是让用户非常直观地听出：

> 增加 Dialogue/Speaker Control 到底是正收益、无收益，还是负收益。

# 21. 用户验收后的决策树

后续阶段必须根据真实结果选择，而不是预设。

## 情况 A

如果：

```text
台词明显更稳定
speaker swap 显著改善
视觉无退化
当前声线已经够好
```

则：

> **不要自动做 Voice Reference。**

下一步优先考虑把 B1 productionize：

```text
generation basis
freshness
default policy
必要 UI / workflow
```

Voice Reference 可以继续不做。

---

## 情况 B

如果：

```text
Dialogue / Speaker 已很好
但同一角色跨镜声音仍明显漂移
```

才进入：

> **B2 Voice Reference Control**

专门验证：

```text
Tier A existing visual path
vs
Tier B reference + voice audio
```

重点比较：

```text
声音一致性收益
vs
视觉一致性损失
```

---

## 情况 C

如果：

```text
multi-speaker 仍频繁 swap
```

不要直接做 Voice Reference。

先分析：

* prompt layout；
* line arrangement；
* single-speaker-per-shot production policy 是否必要；
* Agnes 当前 capability boundary。

最多做一个很窄的 B1.1 prompt/binding 实验。

---

## 情况 D

如果：

```text
加 dialogue block 反而损害视觉
```

立即停止扩展。

调查 prompt coupling。

不要继续往系统里加更多声音控制。

---

## 情况 E

如果：

```text
现有 uncontrolled native audio 已经和 B1 几乎一样好
```

也允许结论是：

> **系统无需增加复杂控制。**

保留最薄的 dialogue injection 即可。

“不增加架构”也是合法成功结果。
