# 动画分镜工作流 — 产品流程与界面设计

> 本文档取代此前的 `REDESIGN_SPEC.md`（该版本第 4 步的界面设想与当前数据模型不兼容，已作废）。
> 阅读顺序很重要：**先读第一部分**，建立"人是怎么用这个工具的"的直觉，再看后面的实现要求。
> 第一部分不是背景介绍，是设计依据本身。后面每一条要求都能在第一部分找到出处。

---

# 第一部分　一个用户完整走一遍

下面是一个真实用户从零做出一条两分钟短片的全过程。请把自己代入这个人，而不是代入实现者。

---

## 他是谁，他在想什么

小周，会写点故事，不懂影视术语，没用过专业剪辑软件。他脑子里有个念头：

> "末世废墟，少年捡到一只坏掉的机械狗。"

他现在只有这一句话。他打开这个工具，想把它变成一条能看的片子。

**他最怕的三件事**：不知道下一步该干嘛、干了半天不知道有没有用、辛苦做的东西丢了。整个产品的设计都是在消除这三件事。

---

## 第 1 步 · 建项目（约 10 秒）

他打开工具，看到一个"新建项目"。

- 起个名字：**废墟同行**
- 画面风格：屏幕上是七张带示意图的卡片（日系动画 / 3D 渲染 / 写实电影 / 水墨 / 美式卡通 / 赛博朋克 / 绘本手绘）。他点了**日系动画**。
- 画幅：三个按钮，他点了 **16:9 横屏**。

**为什么风格在最前面**：这个选择会影响后面每一张图。放在最后等于让他重做。而且这是整个流程里最轻松的一步——点两下就完成，让他先有一个"我已经开始了"的进度感。

**他不需要理解的**：分辨率、size_tier、prompt 后缀怎么拼。这些都不出现在界面上。

---

## 第 2 步 · 造角色（约 2 分钟）

他知道故事里有谁。

- 点"新建角色"，名字写 **阿岚**，描述写：*15 岁少年，灰色斗篷，背着旧登山包，眼神警惕*
- 点"生成三视图"，等几十秒，正面/侧面/背面三张图出来了
- 侧面那张他不满意，点"重新生成"，再等一次，这次可以
- 再造一个 **机械狗**：*小型四足机械犬，装甲磨损严重，右前腿有裸露线路*

**这一步的真正作用不是造角色，是让他看到成果。** 他花了两分钟，屏幕上已经有六张自己造出来的图。这是他继续做下去的动力来源。如果第一步就是"写剧本"，他很可能写到一半就关掉了。

**这一步可以跳过**：如果角色库里已经有他想要的角色，他可以直接进第 3 步，在那里引用库里的角色。

---

## 第 3 步 · 写剧本（约 10 分钟，全程手写）

这一页分上下两块。

### 上面：整个故事

一个大文本框，他写：

> 末世废墟中，阿岚独自搜寻物资。他听到异响，发现瓦砾中一只受损的机械狗。他犹豫后决定修好它。修复过程中两人（一人一机）逐渐建立信任。最后他们一起走向远方的城市轮廓。

**这段文本没有任何人解析它，系统不会读它、不会拆它、不会拿它生成任何东西。**

它唯一的作用是：**他自己的北极星**。写下面每一条分镜时，抬头看一眼，不至于跑偏。所以它必须一直在视线里可及，但不能占地方——做成可折叠的横条，默认只显示第一行，点一下展开。

### 下面：一条条分镜故事

他一条条手写，每条包含：故事文本 + 出场角色（点选，不是打字）。

| # | 分镜故事 | 出场角色 |
|---|---|---|
| ① | 废墟街道，黄昏。阿岚背着包，小心翼翼走过倒塌的建筑，脚下碎石作响。 | 阿岚 |
| ② | 他听到金属摩擦声，猛地转头，看见瓦砾堆里一只机械狗，右前腿冒着火花。 | 阿岚、机械狗 |
| ③ | 阿岚蹲下伸手，机械狗警戒地后退半步，头部传感器红光闪烁。 | 阿岚、机械狗 |
| ④ | 阿岚从包里掏出工具，示意自己没有敌意。机械狗停止后退。 | 阿岚、机械狗 |
| … | … | … |

一共写了 8 条。

**这里他写的是"发生了什么"，不是"怎么拍"。** 没有任何一个字段问他景别、机位、光照——那是导演的活，现在他还在当编剧。让他现在做这件事，他会卡住。

**角色是点选的**，从第 2 步造好的角色里选。这有两个好处：他不会写错名字；系统百分百知道这条要用哪张参考图。

**没有 AI 自动拆分。** 一条分镜故事就是他认为的一个场景，颗粒度由他决定。这是本产品和市面工具最大的区别——那些工具的复杂大半来自"AI 自动拆 → 拆得不对 → 人回去改 → 改完又要重拆"这个循环。这里没有这个循环。

写完，点"保存剧本"。

---

## 第 4 步 · 做分镜（主战场，一小时以上）

进入这一页，**整个故事不再显示**——它的使命在上一步已经结束了。

左边是他刚写的那 8 条，每条一行。他点了**第 ② 条**。

右边显示：

```
② 他听到金属摩擦声，猛地转头，看见瓦砾堆里一只机械狗，右前腿冒着火花。
   出场：[阿岚缩略图] [机械狗缩略图]
```

- 上面那句话是**他自己写的原文，只读**。他一眼就想起当时的意图。
- 旁边是两个角色的参考图缩略图，锁定状态。他知道这条生成时一定会用这两张脸。
- 下面是空的，只有一个 **「+ 添加镜头」**。

**现在他的脑子切换了。** 他不再是编剧，是导演。他要决定这段怎么拍。他加了两个镜头：

**镜头 1**
- 景别：中景
- 画面：*阿岚侧脸，猛地转向声源方向，斗篷因动作扬起*
- 台词：（无）

**镜头 2**
- 景别：特写
- 画面：*瓦砾中的机械狗，右前腿裸露线路火花闪烁，头部红光缓慢转动*
- 台词：（无）

第 ③ 条他可能只加一个镜头，第 ⑦ 条他可能加四个。**颗粒度完全由他决定。**

### 中文写完，点一下翻译

每个镜头的"画面"输入框右边有一个小小的**翻译按钮**。

他写完中文，点一下，等两三秒，下面出现英文提示词。他可以直接改这段英文，也可以不管。

**为什么要单独一步，而不是生成时自动翻译**：如果合在一起，他点"生成首帧"后要等一分钟，中间不知道系统在干什么。分成两步，他先等 3 秒看到翻译结果（"哦它在翻译"），再等 40 秒看到图（"哦它在画图"）。**同样的总时长，焦虑感完全不同——他始终知道自己在等什么。**

### 四段流水线

每个镜头卡片下面是一条状态清晰的流水线：

```
首帧 ✓ ─── 配音 ✓ ─── 尾帧 — ─── 视频 ⏳ 62%
```

每一段可点击执行，失败点击重试。他一段一段推进，或者点右上角"本场景一键生成"让它自己跑。

**他关掉浏览器去吃饭，回来进度还在。** 这是已经做好的能力（任务队列 + 断点续跑），但界面必须让他看得出来。

---

## 第 5 步 · 导出（几分钟）

一个检查清单先告诉他哪里还缺：

```
✓ 18 个镜头已生成视频
⚠ 2 个镜头未配音（第③条镜头2、第⑦条镜头1）—— 将静音播放
✓ 字幕已生成

预计成片  2 分 34 秒 · 16:9
```

他补完那两个配音，点"合成并下载"。

---

## 小周全程做的决定

按顺序列出来，这就是产品的骨架：

1. 项目叫什么、什么风格、什么画幅
2. 有哪些角色，长什么样
3. 整个故事讲什么（写给自己看）
4. 拆成哪几条分镜故事，每条有谁
5. 每条分镜故事拍几个镜头，每个镜头什么景别、什么画面
6. 每个镜头的中文要不要翻译、翻译得对不对
7. 哪些镜头要重做

**他全程没有被要求理解**：数据模型、prompt 拼接、限流、公网 URL、link_mode、num_frames、size_tier。这些一个都不该出现在界面上。

# 第二部分　这套流程对应的数据分层

用户视角的东西落到数据上，是三层：

```
项目 Project ── 风格、画幅、整个故事（纯文本，不解析）
  ├─ 角色 Character ── 名字、描述、三视图
  └─ 分镜故事 Scene ── 用户手写的故事文本、出场角色
        └─ 镜头 Shot ── 景别、画面描述(中/英)、台词、机位光照动效、首帧尾帧配音视频
```

**关键：故事层和拍摄层字段完全不重叠。**

| 层 | 用户在哪一步填 | 字段 |
|---|---|---|
| 分镜故事 Scene | 第 3 步 | 故事文本、出场角色 |
| 镜头 Shot | 第 4 步 | 景别、画面描述、台词、机位、光照、动效、接续方式 |

因为不重叠，所以**"用户改了剧本，已生成的镜头怎么办"这个问题不存在**——剧本层压根没有镜头的字段，改剧本只会改那段故事文本，不会覆盖任何镜头。

# 第三部分　各页面实现要求

## 3.0 全局

### 顶部步骤条

```
① 项目 ✓ ── ② 角色 ✓ ── ③ 剧本 ✓ ── ④ 分镜 ⏳ ── ⑤ 导出 ○
  废墟同行     2 个角色     8 条分镜     5/12 镜头    未就绪
```

各步状态定义：

| 步骤 | 解锁条件 | ⏳ 进行中 | ✓ 完成 |
|---|---|---|---|
| ① 项目 | 始终 | 已建项目未选风格 | 已选风格 + 画幅 |
| ② 角色 | 已有项目 | 有角色但三视图未全 | 至少 1 个角色有完整三视图（**可跳过**，跳过后显示"已跳过"） |
| ③ 剧本 | 已有项目 | 有分镜故事未保存 | 已保存 ≥1 条分镜故事 |
| ④ 分镜 | 剧本已保存 ≥1 条 | 有镜头未完成 | 所有未锁定镜头 video=done |
| ⑤ 导出 | ≥1 个镜头有视频 | — | 已生成成片 |

未解锁的步骤置灰，点击给出具体理由（复用现有"按钮禁用 + 黄色提示"模式）。

### 保留

- 左侧列表的视觉风格（用户认可）
- 顶栏「队列」面板（全部功能正常）
- 顶栏「编排」弹窗（全部功能正常）
- SSE 实时进度与断线降级（已实测四种中断场景）

### 移除

- 侧边栏四个平级导航项（被步骤条取代）
- 「绑定到项目」按钮（系统概念，不该暴露给用户）
- Settings 页 7 个死控件
- TabSheet「+ 添加裁剪框」（点了只弹 toast）
- ShotCard「去音频页生成」文案（指向已删页面）

### 术语（面向用户，不面向系统）

| 现在 | 改成 |
|---|---|
| Dashboard / Characters / Storyboard | 项目 / 角色 / 分镜 |
| link_mode: i2v / keyframes / none | 接续方式：图生视频 / 首尾帧过渡 / 不接续 |
| 「重新托管」 | 「修复图片链接」 |
| 「保存并解析」 | 「保存剧本」 |

按钮说什么，结果提示就说什么：点「保存剧本」，提示是「剧本已保存」。

## 3.1 第 1 步：项目

**要修的现状问题**：`createProject` 接口存在但没有任何新建入口（只能靠 ShotBoard 下拉选已有项目）；剧本页的「尺寸」下拉在 v1→v2 迁移时被直接丢弃，填了不生效。

### 布局

```
┌──────────────────────────────────────────────┐
│  项目                           [+ 新建项目]  │
├────────────┬─────────────────────────────────┤
│ 废墟同行    │  项目名 [废墟同行          ]    │
│ 8 分镜·12镜 │                                │
│            │  画面风格                       │
│ ▶ 星际迷航 │  ┌───┐┌───┐┌───┐┌───┐        │
│ 3 分镜     │  │日系││3D ││写实││水墨│ ...   │
│            │  └───┘└───┘└───┘└───┘        │
│            │    ▲已选                        │
│            │  画幅  [16:9] [9:16] [1:1]      │
│            │                                 │
│            │           [ 下一步：角色 → ]    │
└────────────┴─────────────────────────────────┘
```

### 风格预设

改自由文本为卡片选择。每个预设写入 `StyleAnchor`，且**要填满多个字段**，不只 `art_style`：

| 显示名 | art_style | palette |
|---|---|---|
| 日系动画 | `anime, cel shading, soft lighting` | `soft pastel` |
| 3D 渲染 | `3D render, pixar style, subsurface scattering` | `warm saturated` |
| 写实电影 | `photorealistic, cinematic lighting, shallow depth of field` | `desaturated teal-orange` |
| 水墨 | `chinese ink wash painting, minimal` | `monochrome ink` |
| 美式卡通 | `western cartoon, bold outlines, flat color` | `bright primary` |
| 赛博朋克 | `cyberpunk, neon lighting, rain-slicked streets` | `neon magenta and cyan` |
| 绘本手绘 | `hand-drawn storybook illustration, watercolor texture` | `warm earth tones` |

外加「自定义」卡片，点开才显示自由文本框（`art_style` / `palette` / `era` / `extra` 四个字段），给高级用户留后门但不占默认视线。

实际 prompt 片段需实测微调（生成几张图看效果），上表是起点不是定稿。

### 画幅

- **先实测**：9:16 和 1:1 各发一次真实视频请求，确认服务端接受、返回尺寸正常。免费，约 3 分钟。
- 实测通过 → 三个都开
- 未通过 → 只开 16:9，另两个显示灰色「暂不支持」并说明原因

**绝对不能**让用户在第 1 步选了 9:16，跑到第 4 步生成视频才失败——那是最难定位的失败位置。

### 「尺寸」下拉整个删除

它现在填了不生效（迁移时被丢弃），视频尺寸由画幅推导（16:9 → 1280×704）。`size_tier` 固定 1K，不暴露。

### 改风格的保护

项目已有生成产物时改风格，弹确认：

> 改风格不会删除已生成的画面，但新画面会和旧的不一致。建议改完后重新生成全部首帧。

不阻止，只说清后果。

## 3.2 第 2 步：角色

**要修的现状问题**：页面加载不调 `getProjectCharactersFull`，左侧列表永远是空的；「+添加角色」只存内存，刷新就没了；角色散落三处（剧本定义/页面新增/角色库）用户看不出关系；视图键名 `full`/`back` 不统一。

### 布局

```
┌──────────────────────────────────────────────┐
│  角色                  [+ 新建角色] [从库导入] │
├────────────┬─────────────────────────────────┤
│ ● 阿岚  ✓  │  阿岚                           │
│            │  [15岁少年，灰色斗篷，背旧登山包] │
│ ● 机械狗 ✓ │                                 │
│            │  三视图                          │
│ ○ 商人  ○  │  ┌────┐┌────┐┌────┐           │
│   待生成    │  │正面││侧面││背面│            │
│            │  │ ✓  ││ ✓  ││ ✓  │           │
│ ＋         │  └────┘└────┘└────┘           │
│            │                                 │
│            │  [重新生成三视图] [保存到角色库]  │
│            │  ▸ 高级：单视角 / 设定图裁剪      │
└────────────┴─────────────────────────────────┘
```

### 要求

1. **页面加载必须调 `getProjectCharactersFull`**，把项目角色显示出来（这是列表永远为空的直接原因）
2. **「新建角色」立即落盘**到项目，不再只 push 内存
3. **删除「绑定到项目」按钮**，三视图生成完成即自动落盘到项目
   - 实现方式待定：改造生成接口使其感知 project + 角色名，或前端生成后自动调 bind。选一个，不要留给用户
4. **「从库导入」是抽屉里的一次性动作**，不再作为并列的第三套数据常驻显示。导入后它就是本项目的角色
5. **「保存到角色库」保留**，语义清晰：存起来给别的项目用
6. **三种生成方式分主次**：默认「一键生成三视图」，单视角/设定图裁剪收进「▸ 高级」
7. **键名统一为 `front`/`side`/`back`**，存量数据（`我的动画短片` 用的是 `full`）做一次性迁移，然后删除兼容垫片——阶段 5 刚清完垫片，不要重新引入

### 物品/道具

**本期不做。** 它和角色共用同一套机制，属于第 2 步的扩展。等新流程真跑完一部片子再决定它的形态。剧本里可以完全没有物品，只有人物。

## 3.3 第 3 步：剧本

**要修的现状问题**：剧本编辑器**只写不读**（`api/index.ts` 里没有任何读取已存剧本的方法），每次打开角色/场景列表都是空的——这是"数据丢了"感受的主要来源。

### 布局

```
┌──────────────────────────────────────────────────┐
│  剧本                              [ 保存剧本 ]   │
├──────────────────────────────────────────────────┤
│ ▾ 整个故事                                        │
│ ┌──────────────────────────────────────────────┐ │
│ │ 末世废墟中，阿岚独自搜寻物资。他听到异响，     │ │
│ │ 发现瓦砾中一只受损的机械狗...                 │ │
│ └──────────────────────────────────────────────┘ │
├────────────┬─────────────────────────────────────┤
│ ① 废墟街道 │  分镜故事 ②                         │
│   阿岚      │  ┌───────────────────────────────┐ │
│            │  │ 他听到金属摩擦声，猛地转头，   │ │
│ ▶② 发现    │  │ 看见瓦砾堆里一只机械狗，       │ │
│   阿岚机械狗│  │ 右前腿冒着火花。               │ │
│            │  └───────────────────────────────┘ │
│ ③ 试探     │                                     │
│   阿岚机械狗│  出场角色  [阿岚 ×] [机械狗 ×] [+] │
│            │            ↑ 从第2步的角色里点选     │
│ ＋ 添加分镜 │                                     │
└────────────┴─────────────────────────────────────┘
```

### 要求

1. **「整个故事」是可折叠横条**，默认只显示第一行，点开展开。它服务于"写分镜故事"这个动作，写完使命结束
2. **「整个故事」纯文本，不解析、不拆分、不参与任何生成**。系统对它唯一的操作是保存和显示
3. **必须能回显**。需要新增读剧本接口（后端 v2 → 前端表单），页面加载时拉取。没有它剧本页永远不可用
4. **出场角色是多选控件**，选项来自第 2 步的角色 + 角色库。不允许手打
5. **不做 AI 自动拆分**。一条分镜故事就是用户认为的一个场景，颗粒度由用户决定
6. **不出现任何拍摄字段**（景别、机位、光照、动效）——那些属于第 4 步
7. 左侧列表项显示：序号 + 故事文本前 6–8 字 + 出场角色名
8. 分镜故事支持拖拽排序、删除（删除需二次确认，明确告知会连带删除该条下已生成的镜头和视频）

### 数据源

**`project.json` 是唯一真相源。** YAML 降级为导入/导出格式，`script_parser` 从"解析器"变成"导入器"。

理由：`parsed_script.json`（v1）和 `project.json`（v2）双写分裂已经造成实际事故（`我的动画短片` 里两份文件的角色分别是"战斗机甲"和"小星/暗影"）。保留 YAML 作为存储格式等于把同一个坑换个名字再挖一遍。用户从来不看 YAML，存储格式对他没有意义。

### 保存时的增量保护

- 按 `scene_id` 匹配：已存在的分镜故事**只更新故事文本和出场角色**，其下的镜头及所有产物原样保留
- 新增的分镜故事 → 追加新 Scene，无镜头
- 删除的分镜故事 → 二次确认，明确告知连带影响
- 因为故事层和镜头层字段不重叠，不存在"改剧本覆盖镜头字段"的问题

## 3.4 第 4 步：分镜

**要修的现状问题**：ShotCard 没有配音按钮（`generateShotAudio` 接口闲置，配音只能靠编排器批量）；`splitDialogue` 同样闲置；**没有任何"手动添加镜头"的入口**（这是当前数据模型产不出"同场景多镜头各有独立景别"的直接原因）；所有场景的镜头堆在一个页面滚动。

### 布局

```
┌────────────────────────────────────────────────────────┐
│  分镜                  [本场景一键生成] [队列] [编排]   │
├────────────┬───────────────────────────────────────────┤
│ ① 废墟街道 │ ② 他听到金属摩擦声，猛地转头，看见瓦砾堆里  │
│ ●●  2/2 ✓  │   一只机械狗，右前腿冒着火花。   （只读）  │
│ [缩略图]    │   出场：[阿岚▣] [机械狗▣]                 │
│            │ ───────────────────────────────────────── │
│ ▶② 发现    │ ┌───────────────────────────────────────┐ │
│ ●○  1/2    │ │ 镜头 1   景别[中景▾]            🔓    │ │
│ [缩略图]    │ │ 画面 [阿岚侧脸，猛地转向声源...] [译]  │ │
│            │ │ 英文 [Alan's profile, snapping...]    │ │
│ ③ 试探     │ │ 台词 [                          ]     │ │
│ ○○  0/1    │ │ ▸ 机位 / 光照 / 动效                  │ │
│            │ │ 首帧✓ ─ 配音✓ ─ 尾帧— ─ 视频⏳62%    │ │
│ ＋         │ │ 接续方式 [图生视频 ▾]                 │ │
│            │ └───────────────────────────────────────┘ │
│            │ ┌───────────────────────────────────────┐ │
│            │ │ 镜头 2   景别[特写▾]                  │ │
│            │ └───────────────────────────────────────┘ │
│            │           [ + 添加镜头 ]                  │
└────────────┴───────────────────────────────────────────┘
```

### 要求

1. **保存剧本后，全部分镜故事一次性导入左侧列表**，不是一次导一个
2. **右侧只显示当前选中的那一条**，绝不上下堆叠所有场景
3. **顶部显示用户手写的故事原文（只读）+ 锁定的出场角色缩略图**。这是他重建当时意图的锚点
4. **「整个故事」不在这一页显示**
5. **新增「+ 添加镜头」能力**（当前完全没有）。新镜头继承所属 Scene 的 `scene_id` 和出场角色，其余字段空白待填
6. **镜头字段可编辑**：景别、画面描述（中文）、英文提示词、台词。机位/光照/动效收进折叠区（进阶参数）
7. **左侧列表项显示**：序号 + 故事前几字 + 进度圆点 + 完成数 + 首帧缩略图（用户靠画面认场景比靠文字快）

### 翻译按钮（本次新增）

- 位置：中文"画面"输入框右侧的小按钮
- 行为：调用 Agnes 文本模型把中文画面描述译成英文提示词，填入下方"英文"框
- **英文框可手动编辑**
- **不在生成时自动翻译**。把一次长等待切成"翻译 3 秒 + 生成 40 秒"两段，用户始终知道自己在等什么
- 未翻译就点生成：不阻止，但提示"当前将直接使用中文描述生成，建议先翻译"

### 四段流水线

```
首帧 ✓ ─── 配音 ✓ ─── 尾帧 — ─── 视频 ⏳ 62%
```

- 状态：`— 不适用` / `○ 待生成` / `⏳ 进行中(带%)` / `✓ 完成` / `✗ 失败`
- 每段可点击执行，失败态点击 = 重试
- 尾帧仅 `link_mode=keyframes` 时可用，其余显示灰色 `—`，悬停说明"当前接续方式不需要尾帧"

**配音必须走 JobQueue**：现在 `POST /shot/{id}/audio` 走的是 `background_tasks + task_store`，不进 JobQueue，所以配音任务在队列面板里看不见，和其余三段行为不一致。改为提交 audio job，四段统一。

### 补上缺失的入口

- **配音按钮**（流水线第二段），调 `generateShotAudio`
- **台词拆分**：后端返回 `needs_split` 时，卡片上显示黄色提示 + 「拆成两个镜头」按钮，调 `splitDialogue`。现在用户看到警告却无法操作

### 场景级批量

「本场景一键生成」= 作用域限定当前分镜故事的 orchestrate。现有编排器是全项目的，颗粒度太粗。

# 第四部分　实施顺序与验收

每交付一批，用户测一批，通过了再做下一批。

| 批次 | 内容 | 怎么测 |
|---|---|---|
| **0 地基** | `project.json` 统一为唯一真相源；剧本/角色写 v2；新增读剧本接口；Scene 增加"故事文本"字段；存量 v1/v2 分裂修复；`full`→`back` 键名统一 | 界面无变化。剧本页改一句话保存 → 分镜页刷新能看到；角色页新建角色 → 分镜生成首帧时该角色参考图生效 |
| **1 框架** | 顶部步骤条 + 导航改造 + 术语统一 | 五步都能看到，未解锁步骤点击有明确提示 |
| **2 项目页** | 新建项目 + 项目列表 + 风格卡片 + 画幅按钮；删「尺寸」下拉；**先做画幅实测** | 建新项目 → 选日系动画 + 16:9 → 进第 2 步 |
| **3 角色页** | 加载项目角色 + 三来源合一 + 新建即落盘 + 删「绑定」+ 高级区收纳 + 键名迁移 | 新建角色 → 生成三视图 → **刷新页面角色还在** |
| **4 剧本页** | 整个故事折叠条 + 分镜故事列表 + 角色多选 + 回显 + 增量保存保护 | 写 3 条分镜故事保存 → 刷新内容还在；改第 3 条 → 第 1、2 条已生成的镜头不丢 |
| **5 分镜页** | 左列表右详情 + 故事原文只读 + **添加镜头** + 镜头字段编辑 + 翻译按钮 + 四段流水线 + 配音入口 + 拆分入口 + 场景级批量 | 选一条分镜故事 → 加两个镜头 → 各设景别 → 翻译 → 逐段生成 |
| **6 导出页** | 就绪检查 + 时间轴 + 合成下载 + 历史命名 | 缺配音的镜头能被检查出来 |
| **7 清理** | Settings 缩减 + 删死控件 | 页面上不再有点了没反应的东西 |

**批次 0 不能跳过也不能后置。** 不修地基，用户按新流程走到第 4 步会发现前面建的角色和剧本全部不生效——这不是 bug，是当前架构决定的必然结果。
