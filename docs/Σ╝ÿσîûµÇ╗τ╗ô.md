## 一、优化方法逐项总结

### 1.1 统一角色视角命名（full → back）
- **改了什么**：`src/pipeline/character_gen.py` 的 `VIEW_NAMES` 从 `[front, side, full]` 改为 `[front, side, back]`，`VIEW_PROMPTS` 的 `full` 键改为 `back`；`api_server.py` 的 `get_project_characters` / `get_project_characters_full` 读取时加 `full→back` 兼容映射。
- **为什么**：前端三个 Tab 和 `api_server.py` 单视角接口都用 `front/side/back`，唯独 pipeline 用 `full`（full 实际是背面）。前端生成的图就算存进项目，字段名也对不上 pipeline 的分镜生成（`storyboard_gen` 读 `reference_images.front`）。这是数据断裂的命名层。
- **效果/验证**：`GET /api/projects/我的动画短片/characters` 返回的 `reference_images` keys 现在统一为 `[front, side, back]`（旧 full 自动映射）。

### 1.2 角色生成结果落盘到项目（修复核心数据断裂）
- **改了什么**：
  - 后端新增 `POST /api/project/{project}/character/bind`：把角色页生成的三视图（base64）落盘到 `projects/<项目>/output/characters/{name}_{view}.png`，并写入 `parsed_script.json` 的 `characters[].reference_images`。
  - 新增 `PUT /api/project/{project}/character/{name}`：更新角色名/描述，改名时同步重命名文件（含 `_seg.png`）+ 更新场景角色名。
  - 前端 `characters/index.vue`：加「绑定到项目」按钮 + 当前项目标签；`saveName/saveDesc` 改为调后端同步（原本只改本地，刷新即丢）。
- **为什么**：角色页生成的图原本只在 `store.characterCache`（内存）和 `saved_characters/`，**没进当前项目的 `output/characters/`**，导致分镜阶段 `storyboard_gen` 拿不到角色参考图，角色一致性全靠文字 prompt 硬撑。这是整个流程第一个、也是最严重的断点。
- **效果/验证**：用临时项目验证 bind 接口——三视图落盘、`parsed_script.json` 的 `reference_images` 路径写入、改名时文件重命名 + 场景角色名同步，全部通过。

### 1.3 剧本编辑器
- **改了什么**：新增 `src/views/script-editor/index.vue`（结构化编辑：项目信息 + 角色列表 + 场景列表，每场景字段 id/description/characters/camera/lighting/motion/dialogue）；路由 `/script-editor` + MainLayout 菜单「剧本」；后端 `POST /api/project/{project}/script` 保存 YAML 到 `input/{project}.yaml` 并调 `ScriptParser` 解析为 `parsed_script.json`（保留已有生成结果与角色参考图）。
- **为什么**：原 `dashboard` 用 mock 数据拼 YAML，没有真正的剧本编辑入口。
- **效果/验证**：临时项目保存剧本 → HTTP 200，`parsed_script.json` 正确生成（1 角色 + 2 场景），YAML 文件落盘到 `input/`。

### 1.4 分镜生成前端接入
- **改了什么**：后端 `POST /api/project/{project}/scene/{scene_id}/generate-storyboard`（后台任务，自动取场景角色 `front` 图作 `image_refs`，单候选快速生成，写回 `parsed_script.json` 的 `image_path`）；前端 `storyboard/index.vue` 加「生成分镜」按钮，**用 SSE 订阅任务进度**（替换原 `prompt()` 编辑暂保留）。
- **为什么**：分镜页原本吃 mock 数据、无生成按钮、编辑用原生 `prompt()`。
- **效果/验证**：接口逻辑验证通过；实际生成依赖 Agnes（当前阻塞）。

### 1.5 视频生成打通（Agnes 视频 API）⚠️ 待实测
- **改了什么（已完成）**：`agnes_client.py` 加 `proxy` 支持（从 `config.yaml` 读）；`api_server.py` 所有 Agnes 图片下载的 `httpx.AsyncClient` 统一加 `proxy=_AGNES_PROXY`。
- **待做**：`agnes_client.generate_video` 的视频 URL 字段解析（当前 `remixed_from_video_id` 疑似 bug，需实测确认真实字段）；新增 `/api/video/generate-scene`（ti2vid 单图）和 `/generate-transition`（keyframes 双图）；`animation/index.vue` 接入真实生成 + ffprobe 读时长。
- **阻塞原因**：~~Agnes API 服务器（`apihub.agnes-ai.com`，Cloudflare 后）当前 TLS 握手被 reset，需启动 Clash 代理（7890）~~。**已于 2026-07-29 解决**：Agnes 官方上线国内入口 `apihub.agnes-ai.cn`，国内直连无需代理；`config.yaml` 已切到 `.cn`，`proxy` 置空。视频 URL 字段实测为 `url`（非 `remixed_from_video_id`），`agnes_client.poll_video` 已用 fallback 链取值。

### 1.6 音频生成打通
- **改了什么**：`api_server.py` 的 `generate_all_audio` 从「只统计数量」改造为真正调用 `MimoTTSClient.synthesize`（后台任务，生成 mp3 + srt，写回 `parsed_script.json` 的 `audio_path`）；新增 `POST /api/project/{project}/audio/{scene_id}/generate`（支持 voice/speed，让前端 TTS 设置生效）；`tts_gen.py` 的 `generate` 加 voice/speed 参数；前端 `store` 的 `generateAllAudio`/`regenerateAudio` 改为真正生成 + 任务轮询，`audio/index.vue` 传 TTS 语速。
- **为什么**：原 `generate_all_audio` 只返回"需要生成 N 个音频，请运行工作流"，不真生成；前端 TTS 设置无效；`handlePlay` 裸 `new Audio`。
- **效果/验证**：代码逻辑验证通过（调用了 mimo、处理了异常、写回逻辑正确）；实际生成受 MIMO_API_KEY 失效阻塞（401）。

### 1.7 SSE 实时进度推送 + 任务系统
- **改了什么**：后端新增 `task_store`（dict，支持多任务，替代全局单例 `current_task`）+ `GET /api/task/{task_id}/stream`（SSE，`StreamingResponse` + `text/event-stream`，每秒推送状态直到 completed/failed）；`get_task_status` 兼容新旧任务系统；前端 `src/composables/useTaskStream.ts`（`EventSource` 订阅）；`storyboard` 改用 SSE 替换 `setTimeout` 轮询。
- **为什么**：原前端每 2 秒 `setTimeout` 轮询，视频生成可能数十分钟，体验极差；全局单例 `current_task` 不支持多任务。
- **效果/验证**：`compose` 任务触发 SSE 订阅，`Content-Type: text/event-stream`，收到 `status=completed` 推送事件。

### 1.8 最终视频合成（ffmpeg）✅ 里程碑
- **改了什么**：新增 `src/pipeline/video_composer.py`（`subprocess` 调 ffmpeg）：每场景有 `video_path` 用视频段，否则用 `image_path` 做 Ken Burns（zoompan 推拉）；统一尺寸/帧率/编码后 `concat` 拼接；叠加各场景 `audio_path`（`adelay` 按时间偏移 + `amix` + `apad` 延伸到视频长度，避免 `-shortest` 截断视频）；后端 `POST /api/project/{project}/compose`（后台任务 + 进度回调）。
- **为什么**：原 `composer.py` 只生成 HTML 分镜板 + JSON 报告，**没有拼成最终 mp4**。
- **效果/验证**：用「我的动画短片」3 张分镜图 + 2 段音频，合成出 **12.0 秒、h264 video + aac audio、1280x720@24fps 的 final.mp4**。Ken Burns + 拼接 + 音频 amix + apad 全部验证通过。

### 2.1 通知系统重构
- **改了什么**：`store/index.ts` 用 Naive UI `createDiscreteApi` 的 `message`（配 `darkTheme`）替换单 `notification` ref；`showNotification` 调 `naiveMessage.success/error/info`，失败回退旧机制。
- **为什么**：原通知单个 ref，后到覆盖先到，3 秒消失，无队列/手动关闭/操作按钮。
- **效果**：Naive UI message 支持队列、手动关闭、动画，体验提升。

### 2.2 去 mock 闪烁
- **改了什么**：`store` 的 `characters`/`scenes` 初始值从 `defaultCharacters`/`defaultScenes` 改为空数组 `[]`。
- **为什么**：原初始化用 mock 数据，加载前会闪一下「小星/暗影」假数据。
- **效果**：刷新页面不再出现 mock 闪烁，由 `loadProject` 加载真实数据。

### 2.3 统一图片 URL 工具
- **改了什么**：新增 `src/utils/media.ts`（`getImageUrl`/`getVideoUrl`/`getAudioUrl`）；`dashboard`/`storyboard`/`animation`/`audio` 四处删除本地重复实现，统一引用。
- **为什么**：`getImageUrl` 在 3 个页面各写一遍，逻辑相同且 `dashboard` 残留 `console.log`。
- **效果**：单一来源，维护方便；图片走 `/api/image`（CORS+缓存），视频/音频走 `/projects` 静态服务。

### 2.5 MainLayout 修复
- **改了什么**：Export 按钮接真实合成（`handleExport` 调 `composeVideo` + SSE 等完成 + 下载 `final.mp4`）；avatar 显示当前项目名首字（原死值 "U"）；页面标题回退改「仪表盘」。
- **为什么**：原 Export 按钮和 avatar 都是死的，无功能。
- **效果**：顶栏 Export 可一键合成并下载视频，avatar 反映当前项目。

### 2.6 清理 console.log + 错误处理
- **改了什么**：`api/index.ts` 的 `request` 方法删除 3 处 `console.log`（请求/响应/数据）；`dashboard` 删除 `getImageUrl` 的 `console.log`；`store` 的 `generateAllAudio`/`regenerateAudio` 错误提示改用 `e.message`（避免 `[object Object]`）。
- **为什么**：大量调试 `console.log` 残留；错误提示 `失败: ${error}` 当 error 是对象时显示 `[object Object]`。
- **效果**：控制台干净，错误提示可读。

### 2.7 api_server.py 拆分（未做，留后续）
- **原因**：1966 行单文件拆成 routers 风险大，易引入回归。当前功能稳定后单独做，拆完跑全流程回归。

### 2.8 httpx 连接池复用（未做，留后续）
- **原因**：当前每次请求新建 `httpx.AsyncClient`。可改为 AgnesClient/MimoClient 持有长生命周期 client，app shutdown 关闭。性能提升有限，优先级低。

## 二、整个项目总结

### 2.1 架构
```
前端 (Vue3 + Naive UI + Pinia + UnoCSS, :7777)
  ├── 剧本编辑 (/script-editor)      ← 1.3 新增
  ├── 角色管理 (/characters)          ← 1.2 加「绑定到项目」
  ├── 分镜画廊 (/storyboard)          ← 1.4 加生成按钮 + SSE
  ├── 动画预览 (/animation)           ← 1.5 待接 Agnes 视频
  ├── 音频管理 (/audio)               ← 1.6 接 TTS
  ├── 仪表盘 (/dashboard)
  └── 设置 (/settings)
  通用：MainLayout(2.5) / useTaskStream(SSE, 1.7) / media.ts(2.3) / 通知(2.1)

后端 (FastAPI, :8000, api_server.py)
  ├── 项目管理 / 剧本保存解析 (1.3)
  ├── 角色绑定到项目 (1.2) / 角色库 CRUD / 场景库 CRUD
  ├── 单场景分镜生成 (1.4) / 批量分镜测试接口
  ├── 音频生成 (1.6) / 视频生成 (1.5 待)
  ├── 最终合成 ffmpeg (1.8)
  ├── 任务系统 task_store + SSE (1.7)
  └── Agnes/Mimo 客户端（代理支持）

AI 服务
  ├── Agnes (文/图/视频) — 需 Clash 代理
  ├── Mimo (TTS) — 需有效 API Key
  └── rembg (本地抠图) + ffmpeg (本地合成)
```

### 2.2 数据流（端到端）
```
剧本编辑器 → 保存 YAML → ScriptParser → parsed_script.json
                                                ↓
角色页生成三视图 → bind 接口 → output/characters/{name}_{view}.png
                              + parsed_script.json.reference_images
                                                ↓
分镜页「生成分镜」→ 取角色 front 图作 image_refs → Agnes 生图
                  → output/storyboards/scene_{id}.png + parsed_script.image_path
                                                ↓
动画页 → Agnes 视频 API（ti2vid 单图 / keyframes 双图）→ output/videos/ (1.5 待)
                                                ↓
音频页 → Mimo TTS → output/audio/dialog_{id}.mp3 + subtitles/scene_{id}.srt
                                                ↓
导出/合成 → VideoComposer (ffmpeg: Ken Burns/视频段 + 音频 amix + apad)
         → output/final.mp4
```

### 2.3 最终视频生成流程（用户视角）
1. **写剧本**：在「剧本编辑」页填写项目信息、角色（英文描述作生图提示词）、场景（中文描述 + 镜头/光照/动作/对白），点「保存并解析」。
2. **生成角色**：在「角色管理」页选角色，用单个/链式/设定图三种方式生成三视图，点「绑定到项目」落盘（分镜生成会引用角色 front 图保持一致性）。
3. **生成分镜**：在「分镜画廊」页选场景，点「生成分镜」，SSE 实时推送进度，完成后图片显示。
4. **生成动画**：在「动画预览」页为每段生成视频（Agnes 图生视频，1.5 待实测）。
5. **生成配音**：在「音频管理」页点「Generate All」，Mimo TTS 生成对白音频 + srt 字幕。
6. **导出视频**：点顶栏「导出视频」，ffmpeg 把分镜图(Ken Burns)/视频段 + 音频 + 字幕合成最终 mp4，自动下载。
