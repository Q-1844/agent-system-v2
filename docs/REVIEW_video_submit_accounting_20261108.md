# 并发提交的额度记账

压缩额度测试继续故障注入发现：即使拿到限流槽后复查余额，两个HTTP POST若在第一个回执到达前重叠，仍可同时通过同一剩余额度检查。原实现12秒测试窗口中两个8秒请求均受理，累计16秒。

新增客户端内的提交记账互斥：取得限流槽后，在锁内重新检查供应商日期闸门和本地余额，执行POST，并在2xx回执后立即记账。轮询和供应商后台生成不在锁内，仍支持两路视频在途。请求明确拒绝或异常时会释放锁，既有非幂等/UNKNOWN保护不变。

两个新增回归分别覆盖慢HTTP回执竞争，以及明确拒收后下一请求仍可提交。并发故障注入从2 POST/16秒变为1 POST/8秒+1次额度等待。包含原有“第二worker等限流槽时获知额度耗尽”的203项关联回归通过；不修改原测试来绕开其屏障。最终全量及真实多窗口接续记录在C仓`docs/HANDOFF_quota_simulation_20261108.md`。
