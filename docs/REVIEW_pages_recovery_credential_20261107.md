# Pages自动恢复：生产密钥403与Contents恢复提交

PR #52的生产密钥探针 [42328905145](https://github.com/Q-1844/agent-system-v2/actions/runs/42328905145) 发现真实配置差异：`FRAME_HOST_TOKEN`可以读取Pages设置、构建状态并写入图片，但`POST /pages/builds`返回403。本地管理PAT的85秒恢复成功不能代替生产密钥验证。

本修复沿用图床已有的Contents写权限：

- 请求重建前验证legacy模式、准确发布分支和根目录；仍不重启building/queued部署。
- Pages重建API返回201时保持原路径。只有明确403时，才在同一仓库、同一发布分支创建恢复标记提交，利用该分支既有的正常推送构建。
- 标记路径由失败部署的commit/created_at/updated_at和分支确定，内容不含凭据或任务文本。GET-first及409/422后的字节核对确保并发、跨实例、响应丢失不会反复创建提交；不覆盖图片或已有标记。
- 任何重建请求或恢复提交都不能代替公网200。失败仍保存到原有独立基础设施等待账本，保护已付费视频并自动续跳。
- 探针调用同一恢复函数；每个显式run/attempt用独立探针ID验证一次新写入，不把已有标记命中误当作密钥写权限通过。全程不调用Agnes。

新增验证覆盖403→恢复提交→真实公共读取、跨实例标记去重、提交响应丢失后的409核对、探针必须有新写入，以及非根目录发布配置拒绝。

修复后的全量、生产密钥探针、原片续跑和最终成片验收结果见本PR与C仓 `docs/HANDOFF_ink_final_20261107.md`。原任务仍为 `ink-diffusion-20m-20261105`，恢复前137个完成视频全部保留；不得将组件验证或RESTORED冒充最终完成。
