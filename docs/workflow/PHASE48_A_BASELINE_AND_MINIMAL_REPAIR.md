## 4. 修复和验证任务

### A06：运行中停止的标签

先复现报告中的 failed/stopped 边界。用户停止导致的中断记录为 stopped 或仓库已有等价 cancellation 语义，保留 stop reason；此前独立发生的模型 / 工具真实错误仍应保留为 failed。不要靠覆盖历史失败来美化状态。

验证停止后结果晚到、人工 continue 前重启、下游 pending、候选落盘和 selected/final 指针。晚到结果可作为未选候选保留，但不能把 stopped run 翻成 success，不能自动派发下游，不能改变 canonical 选择。

### A07：资源发布文件校验

复现 `resource.library.publish_character` 的视图文件缺口。最小修复发布前的真实可读文件 / artifact 校验和错误回执，沿用原有权限、OCC、revision 与 ownership；不要随意把合法外部 artifact 全部判为不存在。

至少验证：合格已存在视图可发布；缺失或无法解析视图阻塞且指针 / revision 不变；合法 Look 复用保持可用。回执应指出失败资产，不只是通用“发布失败”。

### A08：修复目标被旧产物绕过

构造隔离项目：已选旧视频含明确问题；另有同 shot 的普通旧视频但未验证解决该问题。W06/W07 不能因为“有视频、verified=true”便完成。有效修复候选须固定原问题版本，记录问题修复结果与目标满足证据。

若现有系统已经正确阻塞，不新增修复代码，记录回归证据即可。若发现绕过，修正目标验收或 handoff 契约，不能简单全局关闭 reuse；合格旧产物应继续可复用。

### A09：场景目标与单一驱动者

检查 W03/W09 对“稳定地点参考”和“本故事段场景状态图”的要求是否明确。需要夜晚、雨后、门已打开等状态时，应绑定正确 SceneInstance 和版本；仅需地点资料时不强迫生成 SceneInstanceView。

检查同一 project / scope 是否已有运行中工作流、孤立 Agent turn、队列任务。发现重复驱动先查已有接管机制，禁止静默启动两个生产者。保留旧候选和审计记录；不是删除整个项目来消除冲突。

在隔离项目提交一个合法短视频，确认 provider job ID 已持久化后，受控停止本地执行进程 / 服务。恢复时查询同一 job，不再提交同一生成请求；取得真实媒体，验证归属、hash 和回执。记录提交调用次数、同一 provider ID、停止 / 恢复时间与落盘路径。
