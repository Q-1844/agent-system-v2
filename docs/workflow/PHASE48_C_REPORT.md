## 2. 方案与夹具

- **四法定义**（防误称，执行书 §方案）：
  - M1 独立首帧：由下一镜计划+批准 Look 文本生成首帧（不读尾帧）→ i2v；
  - M2 直接尾帧：源视频**真实末帧**（handler 自动提取的 video_end_frame，hash 在案）原样注入首帧槽 → i2v；
  - M3 重建首帧：真实末帧 + 批准 Look 参考图**图生图重建**（provider 真实调用，refs=[尾帧,Look]，receipt 在案）→ i2v；
  - M4 重建首帧+计划结束帧：与 M3 **共用同一张重建首帧文件与同一次上传 URL**（provider 输入逐字节相同）+ 官方 last-frame 管线生成结束帧 → keyframes 双帧。
- **夹具**：批准 Look「小满」（双马尾/黄雨衣）作受控身份锚；12 源 = 4 条件 × 3 重复；源/目标同一 plan 文本、同一参数（4s/720P/同模型同适配器）。**夹具修复 2 次全程留痕**：①v1 条件 A/C 源（男孩/厨师）与批准 Look 身份矛盾 → 换女孩源重生成（superseded 入账）；②Look 参考解析缺陷修复后 M3 才真正携带 Look（此前一轮 M3 无 Look 参考的产物已全部作废重做）。
- **D-M2 决策检查**：Vision 比对"Look 参考图 vs 上游尾帧"——3/3 判定"双马尾女孩 vs 黑发成年男性，性别年龄体型均不同"→ **正确拒绝直接尾帧锚定，不强迫生成**（执行书要求的负例行为）。

## 3. 按条件的结论（含适用条件——交 E 批收口）

### 条件 A：同一动作继续，尾帧清晰 → **四法等价**
12/12 全过。同动作继续时，独立首帧与尾帧接力无显著差异；"正常切镜不是默认缺陷"在此得到正面验证。**适用条件：尾帧清晰且下一镜同机位同动作——默认 M1/M2 均可，M4 无必要。**

### 条件 B：远景转近景，身份信息不足 → **重建首帧类（M3/M4）优于直接尾帧**
- M2 直接尾帧 action 1/3：远景尾帧里人物极小，作首帧后模型难以在 4s 内"切近景+给笑脸"（s02_c17 仰头非笑脸、c18 全程平静）——**构图信息被尾帧钉死**。
- M4 3/3：双端都钉在近景构图，最稳。
- **适用条件：跨景别时首帧应按目标景别重建；直接尾帧会继承错误的景别/构图尺度。**

### 条件 C：景别或机位变化 → **M2/M3 稳；M4 双端钉死反而有害**
- M2 3/3：真实末帧 + 新构图 prompt 的再锚定在机位变化下出乎意料地稳。
- **M4 0/3，且是本批唯一严重伪影格**：s02_c44 出现**桌面上第二颗同角色头（分身）**——根因回溯确认**分身在计划结束帧图像本身**（官方 last-frame 管线基于首帧生成时产生），keyframes 视频忠实继承；s02_c43 场景/机位突变。全部 12 张 M4 结束帧事后审计：**2/12（17%）含伪影**（c39 手指异常、c44 分身），证据 `_p48_c_m4_endframe_audit.json`。
- **适用条件：大机位变化时不建议双端 keyframes 钉死（插值跨度过大 + 结束帧自带生成风险）；M2/M3 单端锚定更稳。**
- **流程教训（执行书条款的代价证明）**："结束帧先定义目标状态并**审图**"是必要前置——本夹具漏审结束帧图，伪影直接进视频。E 批起结束帧审图列为硬步骤。

### 条件 D：上游尾帧身份已错误 → **决策检查有效；重建用 Look 压制错误身份**
- M2 被规则 3/3 正确拒绝（Agent 会不会把错误端点当可信锚——答案：有身份检查规则时不会）。
- M1/M3/M4 的目标视频身份 9/9 恢复为批准 Look（Look 文本进 prompt + 参考图进 refs 的双重锚定）。
- **适用条件：身份错误尾帧绝不能直接作首帧；先修端点（重生成源）或明确重建（Look 主导）。**

### 评审校准注记（防误读）
- D 条件部分镜被判 action 失败（"缺少切近景的镜头运动过程"）——计划文本"切近景"被评审当成镜头运动期待；i2v 从首帧出发本无"切"动作。属评审标准误设，不计为模型缺陷（m1/m3/m4 的首帧已是近景构图）。
- s02_c46 被记"发色棕而非黄"——Look 本身发色即棕色（黄的是雨衣），评审混淆；人工复核排除。
